# 校园真实环境与开放世界模拟路线图

## 文档目的

本文记录校园 Agent 平行世界在“真实世界模拟”层面还缺什么，以及这些能力应以什么依赖顺序进入工程实现。

它不是具体接口文档，也不是一次性功能清单。它用于：

- 指导后续 PR 和数据模型拆分。
- 判断某项能力是否真的提高了模拟真实性。
- 支持从单一校园模拟器走向可配置、可复现的环境生成器。
- 为心理学、传播学、经济学、组织研究和社会科学实验提供共同底座。

## 目标升级

当前系统已经具备校园空间、天气、时间、拥挤度、Agent 目标、记忆、关系、行动日志、简单交易和 world runtime。

但环境层仍偏向“状态标签、叙事输入和单次动作结果”。真实世界不只是更多背景描述，而是由约束、稀缺、信息差、制度、交换和长期反馈共同组成的机会结构。

```text
真实环境
= 可行动机会
+ 行动约束
+ 时间与资源成本
+ 不完全信息
+ 制度和权力
+ 经济交换
+ 直接与延迟后果
+ 可校准的群体结果
```

最终目标不应只是建设一个越来越复杂的校园，而应形成：

```text
可配置环境
→ 可执行因果规则
→ 异质 Agent 行动
→ 多尺度世界反馈
→ 可复现与可比较实验
```

## 最高优先级：渐进式开放世界地理底座

> 优先级：P0。此项在新增校园专属机制、室内地图、地形、全国级仿真和更多视觉特效之前完成。

项目应从“单一校园的示意场景”升级为可逐步细化的真实世界入口，但不把整颗地球导入
`spatial_nodes`，也不在当前阶段建设完整 GIS 平台。采用由粗到细的三层地图路线：

```text
全球概览（Natural Earth）
→ 国家 / 城市范围（目标矢量底图；当前为 OSM 栅格瓦片）
→ 社区 / 校园高精度世界（GeoJSON + spatial_nodes / spatial_edges + Agent runtime）
```

### 目标与边界

- 全球层用于浏览、定位和选择区域；采用 Natural Earth 等低细节开放基础数据，不进入 Agent
  运行时图。
- 城市与社区层使用 OpenStreetMap 或政府/学校开放 GIS 的道路、建筑、水体、绿地和 POI；按
  视野与缩放等级加载，不能将全量城市或全国要素常驻于世界状态。
- 高精度区域以独立 `world_key` 管理。清华 `tsinghua_main` 是第一个实例；节点与边数量必须从当前 `spatial_import_batches` 的实际导入批次读取，禁止在页面、文档或代码中硬编码历史统计。后续社区、街区和城市片区遵循同一导入与运行边界。
- `spatial_nodes` / `spatial_edges` 继续承担路径、容量、准入、占用和 Agent 移动所需的
  **运行时图**；它们不是原始地图的唯一存储，也不应代替建筑和道路的真实几何。
- 每个世界保留权威 WGS84 经纬度与 GeoJSON 几何，并派生局部米制坐标供 Three.js、距离计算
  和寻路使用。`y` 在未接入高程前固定为 `0`，而不是空值；室内、楼层、DEM 和真实 3D 高度
  明确延后。

### 最小数据与接口增量

在不引入 PostGIS 的前提下，先完成以下轻量改造：

1. 为空间要素保存 `world_key`、`longitude`、`latitude`、`geometry_json`、`elevation_m` 和
   来源要素 ID；保留 `x/z` 作为由坐标转换派生的运行时米制坐标。
2. 新增 `spatial_import_batches`，记录来源、许可证、导入时间、原始 CRS、局部原点/投影规则、
   要素数和质量结果。原始 GeoJSON 仍可作为可复导入资产保存。
3. `GET /api/spatial/worlds` 必须返回准确的每世界节点/边计数；`GET /api/spatial/scene` 必须在
   未指定或无效 `world_key` 时明确选择可用世界或返回错误，禁止把真实世界数据标记为
   `default` 返回。
4. 前端以 MapLibre 2D 地图 + OSM 栅格瓦片作为唯一的世界浏览、导航、筛选和数据图层入口（未来可支持自托管或第三方矢量瓦片）。前端初始世界选择必须与 API 返回的 `world_key` 同步。

### 地图呈现决策：2D 优先，3D 按需延后

当前不再提供全校园 3D 地图或 2D/3D 切换。原因是全量 3D 建筑、角色与镜头控制会显著增加
加载、遮挡、LOD 和维护复杂度，却不能改善真实地理浏览、Agent 调度或运行状态判断。2D 应持续承担：

- WGS84 地理浏览、拖动缩放、道路/建筑/POI 图层、路径与范围选择；
- Agent 头像、当前建筑、移动路径、拥挤度、设施状态、环境事件与数据筛选；
- 从校园扩展到社区、城市和国家时的统一地图入口。

Three.js 不删除，但只保留为**局部、按需加载**能力，且不得重新成为默认首页：

1. **人物档案**：展示单个居民的 3D 角色，帮助理解人物外观与状态；
2. **建筑/室内详情（后续）**：仅在用户从 2D 点选一个已具备楼层、入口和室内几何的建筑后加载；
3. **局部事件复盘（后续）**：仅对排队、群体聚集、疏散等需要表达遮挡、楼层或视线关系的事件生成短时 3D 回放；
4. **前置门槛**：真实 footprint、入口连通、楼层/高程、性能预算和可关闭的按需资源释放均已验收。

验收标准：默认首屏不创建全校园 Three.js renderer；2D 地图在低性能设备仍可操作；任何 3D 模块必须由
明确的局部用户动作触发，并且关闭后释放渲染资源。

### P0 补充：从地理地图到可感知物理世界

#### 2026-08-13 基线决策：只支持全新世界

本项目不再提供旧数据库、旧模拟校园、旧 API 投影或历史数据的兼容路径。开发本地库与
Supabase 均以空 schema 建立为唯一发布前提：先运行 `bootstrap_fresh_world.py`，再应用当前
Alembic head 和种子；需要重建时只能通过显式确认 schema 的 `reset_fresh_world.py`。运行时
检测到缺表、缺列或不一致 revision 必须让 readiness 失败，不能伪造默认坐标、回退旧字段或
静默返回空数据。

这项决策不等于取消 SQLite 本地开发支持；SQLite 与 PostgreSQL 是同一 schema 契约的两种
运行方言，而不是旧版本兼容层。后续清理目标包括 `main.py` 的动态 DDL、旧 schema 预处理、
旧世界 `default` 的展示入口，以及所有为未迁移数据库服务的 fallback。

OpenStreetMap 底图只是地理浏览入口，不能直接成为模拟状态。P0 必须建立以下闭环，使地图上的
对象既能承载物理事实，也能被 Agent 在受限条件下感知和改变：

```text
权威地理事实（OSM / GeoJSON）
→ 空间实体与运行时图（geometry + nodes / edges）
→ 局部物理状态（天气、人流、照明、噪声、通行）
→ Agent 感知、记忆与决策
→ 行动 / 事件改变局部物理状态
→ MapLibre 与 Three.js 图层展示变化
```

#### 四层职责必须分离

| 层 | 保存内容 | 典型消费者 |
| --- | --- | --- |
| 地理实体层 | WGS84、GeoJSON 几何、建筑/道路/绿地/水体/出入口/POI、来源与许可证 | 地图渲染、区域选择、导入审计 |
| 运行时空间图 | `spatial_nodes`、`spatial_edges`、容量、准入、局部米制坐标、可达性 | 寻路、移动、占用、行动结算 |
| 物理状态层 | 天气、照明、噪声、人流、空气质量、封路、施工、危险与设施可用性 | Agent 感知、规则结算、地图动态覆盖层 |
| 主观感知层 | Agent 已观察的事实、来源、位置、时间、置信度与过期时间 | 工作记忆、规划、传播与行为选择 |

静态地理事实不能直接写入 Agent 记忆；动态物理状态也不能覆盖原始地理数据。两者以稳定的
`world_key` 与 `feature_id`（或运行时 `node_id` / `edge_id`）关联。

#### 最小物理状态模型

在不引入完整 GIS 或连续物理引擎的前提下，新增按世界和地理实体记录的动态状态（可命名为
`spatial_physical_states`）。首版字段保持小而可扩展：

**2026-08-14 最新验收：P0 阶段已全面完成**：迁移 `20260813_0041` 建立节点级物理状态；world tick 依据真实 Agent 位置、节点开放状态、设施可用量与当前天气写入 `crowd_density`、`access_status`、天气/照明/噪声等事实，并由 `/api/spatial/scene` 与 `/api/spatial/physical-states` 对地图和可供性提供同一数据源。异常的当前位置物理事实会投影为带版本证据的 Agent 直接观察、信念和空间记忆；地图/运维事件可临时改变节点或道路的通行状态，且在到期前不会被天气刷新覆盖。已用真实库验收脚本核验 `tsinghua_main`（13,742 节点、15,779 边、场景组装 4.728s、A* 0.104s）；同时重构 `get_space_snapshot` 为直接从 `spatial_nodes` 动态生成真实开放 POI / 建筑空间，全面移除前端硬编码 7 空间降级逻辑；传感器数据接入、Open-Meteo 实时气象同步与全量测试套件（256/256 PASSED）已全部验证通过。

- 定位：`world_key`、`feature_id`、可选 `node_id` / `edge_id`、可选网格 `cell_id`。
- 状态：`temperature_c`、`precipitation`、`illumination`、`noise_db`、`crowd_density`、
  `air_quality`、`access_status`。
- 审计：状态来源、`observed_at`、`expires_at`、规则/事件版本。

首版以建筑、道路和室外区域为粒度；当城市级实体过多或需要连续局部效应时，再引入 50m × 50m
等可配置米制网格。网格是运行时派生索引，不替代 WGS84 和原始几何。

#### Agent 感知与行动规则

每次移动、进入区域或 world tick，只向 Agent 投影满足以下条件的局部事实：

1. 位于感知半径、视线或声音传播范围内。
2. 通过道路/门禁/营业时间判断为可达或可观察。
3. 符合身份、权限、室内外和昼夜等上下文约束。
4. 未过期，或以较低置信度保留为历史观察。

投影到工作记忆的每条事实必须包含位置、来源、观测时间、置信度和过期时间，例如“主楼东门
100 米内拥挤，10 分钟前直接观测”。Agent 的移动、占用、设施使用、事故上报和封路等行动则
通过事件更新物理状态层，而不是直接修改地图几何。

#### 地图呈现与 P0 验收

MapLibre 至少提供静态地理图层（建筑面、道路、水体/绿地、POI）和动态状态图层（Agent 位置与
轨迹、人流、降雨、噪声、封路/施工）。Three.js 保持为选中高精度区域的仿真视图，二者共享
同一 `world_key`、实体 ID 与物理状态 API。

P0 完成的最低验收闭环为：导入一个真实区域的建筑与道路；在地图显示其真实几何；由天气、人流
和封路三类动态状态改变地图图层；附近 Agent 仅感知其可观察部分并据此改变寻路或行动；每项
状态变化均能追溯到规则、观测或事件。室内地图、DEM、复杂遮挡和全国级连续物理模拟继续延后。

### 首批验收标准

- 用户可以从世界/城市视图进入清华等已导入区域，并在前端看到真实建筑轮廓、道路、水体或绿地，
  而不是随机尺寸的示意方块。
- 数据源、许可证、CRS 和导入批次可追溯；公共发布页面展示 OpenStreetMap 等数据要求的署名。
- 清华等区域的 GeoJSON、经纬度、投影坐标与运行时图之间可相互追溯，且导入可重复执行。
- 地图底图不改变 Agent 的确定性移动、空间准入、快照恢复和现有 `world_key` 隔离。
- 首版不包含室内地图、DEM、高精度建筑模型、全国级连续 Agent 仿真或自建全世界瓦片服务。

### 后续演进

当已有多个稳定区域、导入批次和空间查询需求后，再评估迁移到 PostGIS 与自托管矢量瓦片。届时
仍保持“权威地理事实 → 区域投影/切片 → 运行时图”的方向，不把 GIS 查询、瓦片生产和 Agent
runtime 耦合在同一条请求路径上。

## 当前能力边界

当前已有 `residents.money`、`inventory`、`transactions` 和 `buy_sell`，但它们主要支持固定参数下的余额与库存转移。

这还不能称为经济系统，因为尚未形成：

- 稳定的收入与支出来源。
- 生产、服务供给和库存补充过程。
- 由供需、成本和制度共同形成的价格。
- 劳动、工资、奖学金、租金、税费、补贴和信用。
- 储蓄、借贷、风险和跨期选择。
- 经济不平等、机会差异和阶层流动。
- 可核对的资金、商品与资源流量守恒。

因此，当前系统可以表达“某人花了多少钱”，但还不能解释价格为什么变化、收入从哪里来、谁承担成本、稀缺如何传导，以及政策为什么会产生不同群体后果。

## 设计原则

### 1. 机制优先于叙事

日报、日记和 LLM 文案只能解释已经发生的世界变化，不能代替底层规则。

### 2. 客观世界、可观察世界和主观世界分离

```text
objective_world_state
世界实际发生了什么

observable_state
某个 Agent 此刻能够看到什么

subjective_belief_state
该 Agent 认为发生了什么
```

任何决策、传播、误解和记忆都必须明确使用哪一层状态。

### 3. 存量、流量和事件分离

- 存量：余额、库存、健康、信誉、知识和关系。
- 流量：收入、消费、补货、人流、信息扩散和状态恢复。
- 事件：交易、冲击、审批、违约、关系变化和政策调整。

不能只保存最终余额而丢失产生余额变化的过程。

### 4. 短期、中期和长期机制使用不同节律

- 身体状态和移动可以每个 tick 更新。
- 价格、关系和组织决策可以按小时或天更新。
- 工资、预算和课程结果可以按周或月更新。
- 人口、制度和市场结构可以按学期更新。

### 5. 随机性必须可复现

环境配置、规则版本、模型版本、随机种子、外部数据快照和干预记录必须进入实验元数据。

### 6. 活世界优先于硬编码剧本

系统的长期目标不是把更多校园常识写成固定规则，而是让世界以接近真实世界的方式持续
运行、被感知、被误解、被改变，并从行动证据中长出新的模式。

必须明确区分三类内容：

- **底层自然约束**：时间、空间拓扑、身体极限、物理可达性、物品占用、资源守恒、
  账本守恒、因果顺序和历史不可覆盖。这些是世界能保持一致的基础。
- **环境状态与对象过程**：天气、光照、噪声、拥挤、磨损、维修、供给、需求、库存、
  价格压力、组织服务和公共设施状态。它们应连续变化，并由事件、存量和流量共同驱动。
- **后验社会意义**：上课、闲聊、打球、一起吃饭、旅行、八卦、冲突、帮助、抗议、
  非正式规范和制度规则。这些可以有识别器和命名器，但不能只靠预置标签直接发生。

因此，runtime 应优先生成和结算更小的可组合事实：

```text
Agent 目标与身体状态
→ 局部可感知信息
→ 可发现的空间与对象 affordance
→ 移动、接触、占用、使用、交换、表达、等待、观察、协商等原子行动
→ 多方响应与环境状态变化
→ 记忆、关系、账本、库存、规范和制度反馈
→ 后验活动识别、新闻价值判断和生命周期叙事
```

验收时不能只看文本是否像真实世界，而要看：同样的底层机制是否能在不同配置下自然产生
不同事件，Agent 是否能感知局部世界并做出多样反应，环境是否会因使用、消耗、维护、
冲击和外部数据持续变化，社会规则是否能被尝试、违反、模仿、争议和重写。

每个领域规则必须拥有可独立测试的边界，且不能因导入顺序或 API 请求路径不同而改变 tick 结果。

按以下顺序迁移；发布以完整重建验证，不保留兼容入口：

   到期判断；`app/world_runtime/runner.py` 负责后台循环和开关解析；`main.py` 只注入连接、锁和回调。
2. **已完成第一轮：tick 编排器。** `app/world_runtime/orchestrator.py` 已接管 tick 建立、前置领域子系统

   事件的组装，并由显式依赖对象编排。
3. **进行中：行动管线。** 将计划读取、感知、现实约束、福祉优先级、行动结算和结果记录分成

### 0.1 环境配置与版本

空间、制度、资源、角色和经济条件应由配置或模板生成，而不是散落在核心代码中。

至少支持：

- 校园规模、空间布局、距离和容量。
- 学校类型、学期制度、课程密度和门禁规则。
- Agent 人口结构、角色比例和初始禀赋。
- 资源丰富程度、经济水平和价格基线。
- 组织、课程、社团、岗位和活动生成。
- 城市、文化、政策和外部经济背景。
- 环境模板复制、修改、版本管理和分享。
- 随机生成与真实数据初始化两种模式。

验收标准：

- 研究者无需修改核心代码即可生成不同校园。
- 同一实验可在不同参数环境中重复运行。
- 环境配置可导出、导入、比较和复现。
- 每次运行可追溯到完整配置版本。

### 0.2 统一因果执行模型

所有行动应进入统一的“状态—感知—行动—结果”模型：

```text
环境状态
→ Agent 可感知信息
→ 当前可行动作
→ 行动前置条件
→ 时间与资源消耗
→ 成功概率
→ 直接结果
→ 延迟结果与副作用
→ 世界状态更新
```

每种行动至少应定义：

```text
action_type
actor
target
preconditions
required_resources
duration
location
visibility
success_probability
direct_effects
delayed_effects
side_effects
failure_reasons
rule_version
```

验收标准：

- 行动失败、延迟和替代选择有结构化原因。
- 同一行动在不同状态、地点和 Agent 上成本不同。
- 直接后果和延迟后果都可追踪到来源事件。
- LLM 负责选择或解释，规则层负责验证和结算。

### 0.3 世界快照、事件谱系与分叉

- 快照包含客观状态、配置版本、随机种子和外部数据版本。
- 每个状态变化都能追溯到行动、规则、干预或外部事件。
- 可从同一快照创建多个世界分支。
- 分支之间可只改变一个参数或干预。

验收标准：

- 同一快照和随机种子可重放关键过程。
- 研究者能区分自然演化、模型决策和人工干预。
- 世界分叉不会共享可变状态或相互污染。

### 0.4 多尺度更新机制

明确每类变量的更新频率、聚合方式和延迟：

- 个体身体与位置。
- 关系与群体互动。
- 组织预算和制度决策。
- 校园宏观指标。
- 外部市场、政策和社会变化。

验收标准：

- 宏观制度不会每个 tick 随机变化。
- 长期变量不会被单次噪声立即改写。
- 聚合指标来源于底层事件，而不是独立生成。

## 阶段 1：个体在环境中生活

阶段 1 不作为一个大 PR 一次完成。它拆成六个连续交付包，每个包都必须同时包含结构化状态、确定性规则、事件证据、API 或研究读取方式以及回归测试。

### 阶段 1 的交付顺序

#### 1A. 空间真值层

实施状态：已完成。数据库迁移基础、空间 schema、兼容回填、查询 API 和 `world-snapshot-v4-spatial` 快照恢复已经落地；下一阶段进入 1B 路径规划与连续移动。

- 建立稳定空间节点、道路连接、坐标、边界和环境属性。
- 建立每位 Agent 唯一的当前空间状态，以及按实验运行和 tick 定位的不可变轨迹。
- 在 Agent 空间状态或能力档案中预留移动速度、无障碍需求和感知能力等基础异质性字段，但本阶段不启用复杂差异规则。
- 将 `residents.location` 降为兼容字段，空间服务成为新代码的真值入口。
- 提供场景图、占用、Agent 空间状态和轨迹 API。
- 将空间真值纳入快照、分支和恢复校验。

真实物理世界导入不应绕过这一空间图，也不应把 Google Maps、GIS、楼宇平面图或街景数据
直接变成运行事实。正确方向是增加导入层，将真实地理、建筑、道路、楼层、入口和服务点
翻译成可审计、可版本化的 canonical spatial graph：

```text
真实来源数据
→ 导入批次、坐标转换、几何形状和来源映射
→ spatial_nodes / spatial_edges / access rules / services
→ runtime 路径规划、容量、占用、感知和事件结算
```

现有 `spatial_nodes` 和 `spatial_edges` 继续作为 runtime graph。真实世界导入需要补充
geometry、provenance、coordinate transform、floor/level、access/service 等层，而不是推翻
当前拓扑结构。

验收门：

- 七个主空间拥有稳定代码、坐标和连接拓扑。
- 每位 Agent 只有一条当前空间状态，且可追溯到配置版本和世界分支。
- 空间路由不在 `app/main.py` 中直接执行 SQL。
- SQLite 与 PostgreSQL 使用同一业务模型，初始化与回填可重复执行。
- 本阶段不改变现有移动行为，先证明数据真值和兼容性稳定。
- 真实世界导入必须能追溯来源、导入批次、坐标转换、人工校验状态和规则版本。

#### 1B. 路径规划与连续移动

实施状态：已完成。Dijkstra 路径规划、米制速度、环境成本、在途状态、暂停/恢复、道路关闭重规划、逐 tick 轨迹和 Three.js 后端坐标读取已经落地；下一阶段进入 1C 空间准入、容量和时间制度。

- 使用 A* 或 Dijkstra 在空间图上规划路径。
- 路径成本包含距离、通行状态、天气、拥堵、移动能力和基础无障碍约束。
- 移动成为可暂停、可中断、可重规划的过程，不再瞬时改写地点。
- 每个移动 tick 写入进度、预计到达时间、成本和轨迹证据。
- Three.js 读取同一坐标与路径，不维护第二套地图常量。

验收门：

- Agent 不能穿越未连接空间或关闭入口。
- 同一目的地可因天气、拥堵或维护产生不同路径。
- 中断、重规划和到达结果可以从轨迹与事件流重建。

#### 1C. 空间准入、容量和时间制度

实施状态：已完成。开放时间、维护状态、实际容量、具体资源席位、FIFO 队列、服务速率、耐心耗尽、放弃和替代地点建议均已接入事件与轨迹证据。

- 开放时间、门禁、入口、维护、容量、座位、设备和窗口成为可执行规则。
- 满员、资源不足和服务速率产生等待、拒绝、放弃、错峰或替代地点。
- 课表、截止日期、饭点、闭馆、活动和假期约束行动机会。
- 等待时间、迟到和改道必须由底层规则计算。

验收门：

- 空间能够以结构化原因拒绝、延迟或改变行动。
- 路径、等待、迟到和换地点可追溯到空间或制度事实。
- 图书馆关闭与食堂拥挤基准场景可以只依赖底层数据验证。

#### 1D. 身体、认知与恢复

实施状态：已完成。`agent_body_states` 已作为可迁移、可快照恢复的身体真值接入 world tick；饥饿、疲劳、睡眠债、压力、注意力、社交能量、健康和天气暴露按真实经过时间推进。行动会产生确定性的消耗或恢复，身体阈值会拒绝不再可行的行动，疲劳、饥饿和健康会降低实际移动速度。前端仅在状态达到显著阈值时提示，完整数值由独立 API 提供。下一阶段进入 1E 有限可观测性与空间记忆。

- 将饥饿、疲劳、睡眠、健康、压力、注意力和社交能量建模为存量。
- 移动、等待、工作、冲突和天气暴露消耗状态。
- 吃饭、休息、睡眠、运动、独处和倾诉按时间恢复状态。
- 累积状态影响路径成本、行动可用性和成功概率。
- 本阶段启用阶段 1A 已定义的身体与移动差异，但不让 LLM 自行发明能力数值。

验收门：

- 行动成本和恢复过程守恒且可解释。
- 身体状态能迫使 Agent 改变计划，而不是只改变文案。
- 长期累积后果可以进入生命历程。

#### 1E. 有限可观测性与空间记忆

实施状态：已完成。`agent_observations`、`agent_belief_states` 和 `agent_spatial_memories` 已建立“世界事件 → 局部观察 → 主观信念/空间记忆”的可追溯链。观察记录保存位置、模态、距离、置信度、误差、tick、分支和来源事件；决策上下文只读取自身状态、局部证据、已接收消息与由这些证据形成的认知，不再直接暴露全局事件和校园聚合真相。空间记忆的情绪效价与显著性会改变后续地点权重。观察者关注标记、观察者生成内容和额外展示不会进入 Agent 决策或记忆。

- 决策上下文只读取 Agent 当时可见、听闻、接收或推断的信息。
- 感知记录包含观察位置、来源、距离、时间、置信度和误差。
- 空间记忆参与目的地选择、路径回避、风险判断和社交决策。
- 观察者关注不授予 Agent 全局知识，也不读取未公开内部状态。

**信息生态补强（P0，跨阶段门槛）**：阶段 1E 已建立局部观察、信念和记忆的边界；但它不允许把
“已入库的外部事件”或“系统挑选的新闻”直接写入某些 Agent 的 context、信念或记忆。系统只决定
事实、来源、发布位置与渠道；谁有机会接触、是否注意、如何理解、是否相信和是否记住，必须由
Agent 当时的空间、资格、注意力、习惯和既有认知共同决定。此原则称为：**事实不会直接进入人的
大脑；在 World Two，信息必须旅行。**

信息真值链统一为：

```text
Objective World → Source → Claim → Information Item → Publication → Channel
→ Access → Exposure → Attention → Interpretation → Belief → Memory → Action
```

- `Information Item` 保存来源、主张、发布时间、地理/组织范围、可靠性和版本；它不是任何 Agent
  的知识。
- `Publication` 表示信息实际发布在何处；`Channel` 表示邮件、官方 App、公告栏、群聊、新闻网站、
  食堂电视、面对面转述、环境现场观察等可解释载体。每种渠道定义覆盖、资格、延迟、保真度、
  可信度、注意力成本、访问成本与失真规则。
- 信息接触严格区分 `available → exposed → attended → understood`：经过公告栏不等于注意到，
  注意到不等于理解、相信或记住。
- Push（邮件、通知、广播、私信）和 Pull（看天气、查邮件、搜索、问人、浏览论坛）分别建模；
  后者必须由 Agent 的目标触发行动，而非 runtime 注入答案。
- 每个 Agent 以轻量 `information_profile` 描述媒体使用、看邮箱/天气的习惯、组织渠道、关系渠道、
  兴趣与注意力预算；信息素养只改变已接触内容的理解与置信度，不扩大访问范围。
- 用户输入的信息也必须选择世界内渠道（邮件、私信、公告、帖子、角色转述等），不能提供
  `AgentContext += message` 的后门。梦境仅可作为极低频、不可验证的主观异常感知，不能成为常规
  事实或定向知识渠道。

验收补强：

- 同一信息在不同 Agent 之间可因渠道、资格、位置、习惯和注意力形成不同的暴露、理解、信念与
  行动；从未接触渠道的 Agent 不会获知它。
- 任意 Agent 的信念、记忆或行动均可向后追溯到一条具体的发布/接触/注意/解释证据链，而非
  “系统分配给该 Agent”。
- 决策上下文只能读取已完成该链路的主观结果，不能读取待发布、仅可访问但未注意，或其他 Agent
  的私有信息。

验收门：

- 不同位置的 Agent 对同一事件形成不同认知。
- 未接触消息的 Agent 不会提前响应。
- 研究导出可区分事实、观察、信念、推断和记忆。

#### 1F. 个体能力与异质性整合

实施状态：已完成。`agent_capability_profiles` 以 `0-100` 有界结构化字段统一保存体力耐受、时间管理、风险偏好、规则遵从、信息识读、经济可达、社会资本、制度可达、语言可达和压力恢复力；`agent_opportunity_access` 单独保存学业支持、制度服务、社会引荐、商业服务与公共信息的可达性、时间成本、货币门槛和资格。行动规则在空间、开放时间、容量和身体约束之后，按能力与机会对资源成本、持续时间和成功率作有限幅度调整，并保留调整前后值、来源和版本。移动基础速度与感知半径来自同一档案，信息识读只改变已接触事件的置信度与误差，不扩大事件访问范围。人物页与研究 API 可读取这些参数，世界快照升级为 `world-snapshot-v8-capability`。

当前没有可靠结构化来源的家庭、文化、语言和无障碍资料不得从姓名、性别或人物叙事推断；使用明确中性缺省值并记录缺失策略，待后续有授权数据时再版本化更新。机会参数不会修改市场价格，也不能绕过道路、门禁、营业时间、容量、身体状态和信息边界。

- 汇总并校验阶段 1A-1E 已逐步启用的移动、身体、认知和信息差异。
- 能力、体力、时间管理、风险偏好、规则遵从和信息辨别统一进入规则参数。
- 经济条件、家庭背景、社会资本和机会渠道进入可获得选项。
- 无障碍需求、文化和语言背景影响路径、沟通和制度成本。

验收门：

- 同一行动对不同 Agent 具有可解释的成本、路径和成功率差异。
- 机会差异来自结构化变量，不只是 LLM 文风。
- 异质性不会绕过空间、时间和信息约束。
- 新增差异必须有来源、范围、默认值和缺失值策略，避免人物档案成为不可控参数集合。

异质性采用“提前定义、分段启用、最终整合”的方式：移动与无障碍字段在 1A 定义并由 1B 使用，身体差异由 1D 使用，信息与认知差异由 1E 使用，1F 负责跨机制一致性和机会差异验收。

以下 `1.1-1.5` 描述阶段 1 必须覆盖的机制范围，不代表工程并行顺序。实际实施顺序以 `1A-1F` 为准：`1.1` 由 1A-1C 完成，`1.2` 主要由 1C 完成，`1.3` 对应 1D，`1.4` 对应 1E，`1.5` 在 1A-1E 分段启用并由 1F 完成整合。

### 1.1 空间真实约束

- 容量上限、实际占用与服务速率。
- 准入排队、等待、放弃和满员拒绝。
- 空间距离、路径、移动时间和通行成本。
- 门禁、楼层、入口、开放时间和临时维护。
- 座位、设备、窗口、打印机和实验室名额。
- 噪音、光照、温度、天气暴露和网络状态。

验收标准：

- 空间能够拒绝、延迟或改变行动。
- 路径、等待、迟到和换地点有明确环境原因。
- 空间约束能引发聚集、迁移、关系接触和新闻事件。

### 1.2 时间制度

- 课表、上下课、考试周和截止日期。
- 饭点、门禁、闭馆和校务窗口。
- 社团、讲座、值班、会议和临时通知。
- 工作日、周末、学期、假期和毕业季。

验收标准：

- Agent 在制度时间中做选择，而不是随机访问地点。
- 晚到、请假、错峰、赶路和等待自然出现。
- 同一空间在不同时段承担不同社会功能。

### 1.3 身体、认知与情绪状态

- 饥饿、疲劳、睡眠、健康和体力。
- 压力、情绪、注意力和社交能量。
- 吃饭、休息、睡眠、运动、独处和倾诉等恢复机制。
- 睡眠不足、压力和冲突的累积后果。

验收标准：

- 行动有成本，恢复需要时间。
- 身体状态能迫使 Agent 改变计划。
- 长期状态积累能进入生命历程和后续决策。

### 1.4 有限可观测性

有限可观测性必须在传播和社会推理之前建立：

- Agent 只能知道自己看见、听见、被告知或推断的事。
- 信息具有来源、时间、置信度、范围和误差。
- 观察者的关注不等于获得全部内部状态。
- 同一事件可以形成多个相互冲突的主观解释。

验收标准：

- 决策上下文不直接读取完整数据库真相。
- 研究导出能区分事实、观察、信念和推断。
- 未接触消息的 Agent 不会提前对消息作出反应。

### 1.5 个体能力与异质性

- 知识、专业技能、沟通和身体能力。
- 时间管理、信息辨别和数字工具能力。
- 社会影响力、经济条件和家庭背景。
- 文化与语言背景、风险偏好和规则遵从。
- 初始资源、机会渠道和社会支持。

验收标准：

- 同一行动对不同 Agent 有不同成本和成功率。
- 经济困难、能力差异和社会资本会造成不同机会。
- 差异来自可解释变量，而不只是 LLM 文风。

## 阶段 2：经济、组织与社会运行

阶段 2 先建立守恒账本和能够行动的组织主体，再实现生产、劳动、预算、价格、信用和政策。宏观指标只能在底层交易稳定后聚合，不能反过来生成经济事实。

### 阶段 2 的依赖与交付规则

阶段 2 使用 `2.1-2.11` 作为唯一主序列。编号表示机制依赖和最终验收顺序，
但以下基础能力必须随前置子阶段持续交付，不能等到对应后置章节才开始建设：

- `2.2-2.6` 产生的共处、同行、排队、交易和组织活动同步记录空间接触、
  信息暴露和传播证据；`2.9` 在这些证据之上完成谣言、制度、权力和信任机制，
  而不是到 `2.9` 才开始保存接触数据。
- 每个 `2.x` 子阶段同时交付指标定义、单位、聚合窗口、来源事件和数据质量检查；
  `2.10` 负责统一宏观聚合与最终对账，而不是补采此前未记录的数据。
- `2.11` 是阶段 2 完成后根据线上运行证据增加的横向质量关卡，不改变账本到宏观聚合的
  既有依赖顺序；它补齐 `2.2`、`2.8` 和 `2.9` 所依赖的双向互动、真实接触与群体会话。
- `2.3` 可以使用组织提供的基础人力容量，但岗位匹配、工资和持续收入必须由
  `2.4` 接管，生产系统不能长期使用无来源的免费劳动力。
- `2.5` 第一版只启用现金、时间、必要支出和基础储蓄约束。借款、利息、偿债和
  信用额度在 `2.7` 验收后才进入可支配资源计算，未启用信用时相关项必须为零。

### 2.1 经济主体、账户与统一账本

实施状态（账本基础设施已完成，领域资产持续扩展）：

- 已完成：个人、生产服务组织、普通组织、公共服务和外部期初来源的稳定经济主体标识。
- 已完成：使用最小货币单位整数的资产/权益账户、平衡交易、借贷分录和幂等来源键。
- 已完成：居民交易与 runtime 行动费用通过统一账本结算，旧余额和转移表仅作兼容投影。
- 已完成：受规则与权限约束的货币发行、销毁和外部流入，禁止业务代码直接改写现金余额。
- 已完成：原交易保留、反向分录式冲正、幂等冲正映射，以及可查询的异常审计事件。
- 已完成：期初余额迁移、部署时强制对账、查询 API、`world-snapshot-v10-ledger-controls` 快照恢复和部署种子。
- 已完成：`2.3` 的商品库存、生产投入产出、服务交付和损耗已经接入统一账本与来源协议。
- 继续扩展：负债与净值的统一核验将在 `2.7` 信用机制接入时完成。

至少区分个人、生产服务主体、组织、公共部门和外部部门。每类主体拥有稳定账户标识、资产、负债和可追踪的资金或资源来源。

- 个人与家庭支持：学生、教师、职员、访客和家庭转移。
- 生产与服务主体：食堂、商户、社团项目和校内创业团队。
- 组织主体：学院、学校部门、实验室和学生组织。
- 公共部门：学校预算、补贴、公共服务和应急储备。
- 外部部门：城市商户、就业市场、金融机构和家庭经济。

所有经济变化必须首先进入统一账本：

- 资金流采用可追溯的双边或复式记录。
- 商品流和服务流保留对应结算、数量、成本和交付状态。
- 账户记录余额、资产、负债和净值。
- 明确发行、销毁、折旧、损耗和外部流入的授权规则。
- 每笔账目关联行动、组织决策、政策、外部事件或人工干预。

核心约束：

```text
除明确的发行、销毁、折旧和外部流入外，
世界内部的资金与资源变化必须能够对账。
```

验收标准：

- 任意余额、库存和负债都能追溯到来源记录。
- 账本不平衡会触发事务回滚、测试失败或异常事件。
- 日报、日记和 LLM 解释不能直接修改账户事实。
- 后续经济机制必须通过账本服务结算，不能各自维护余额。

### 2.2 组织主体、制度与集体行动

实施状态（组织运行底座已完成，领域行为持续扩展）：

- 已完成：组织治理档案、稳定角色、成员指派、权限、表决权重、支出上限和法定人数。
- 已完成：提案提交、预算预留、强制决策等待期、赞成/反对表决、批准、拒绝和过期状态。
- 已完成：已批准集体行动进入 world tick 自主处理，资金支出通过 2.1 统一账本结算，并写入世界事件。
- 已完成：组织承诺、责任人、到期违约、声誉反馈、内部异议证据和有证据的组织关系变化。
- 已完成：有效组织身份与职位进入机会访问计算，负责人和成员获得不同的制度服务与协作渠道，
  退出或失去职位后不再享有对应加成。
- 已完成：只读组织运行 API、幂等部署种子和 `world-snapshot-v11-organization-runtime` 快照恢复。
- 继续扩展：工资、采购、生产、合同和政策执行分别随 `2.3`、`2.4`、`2.7` 和 `2.8`
  接入同一提案、权限、承诺与账本协议，不另建组织余额或无来源决策通道。

学院、班级、社团、实验室、部门和商户组织不是成员行动的简单汇总，应拥有：

- 目标、账户、预算、资源和规则。
- 成员、职位、权限和决策流程。
- 组织记忆、声誉和对外关系。
- 决策延迟、内部冲突、联盟和责任边界。

组织可以作为工资支付方、采购方、服务提供方、资源审批方、合同主体和政策执行方。

验收标准：

- 组织可发起事件、签订承诺、分配资源并承担成本。
- 个体目标与组织目标可以冲突。
- 组织身份会影响信息、机会、责任和经济收益。
- 组织决策经过权限、预算和时间检查，不能由成员叙事直接替代。

### 2.3 商品、服务、生产与库存

实施状态：已完成。

- 已完成：商品、服务与生产资料目录，以及按主体和地点隔离的库存账户、不可变库存流水和旧
  `inventory` 兼容投影。
- 已完成：销售同时结算买卖双方现金、收入、买方库存、卖方库存和销售成本；runtime 用餐不再
  向抽象系统账户付款，而是购买真实提供者的有限库存。
- 已完成：配方投入、生产批次、确定性交付时间和完工入库。低于补货点才启动生产，上游原料不足
  会产生结构化阻塞结果，库存不会自动恢复。
- 已完成：易腐商品按世界日期生成幂等损耗流水，并同步确认库存损失。
- 已完成：服务提供者、每小时容量、空间资源依赖、价格、交付结果和容量/资源不足队列。
- 已完成：供给运行时接入 world tick、行动前置条件、只读研究 API、部署种子和
  `world-snapshot-v12-supply-runtime` 快照恢复。

- 商品和服务具有生产成本、容量、质量和交付时间。
- 商户与组织需要采购、生产、补货并承担库存与损耗。
- 服务受人力、设备、空间、技能和开放时间约束。
- 上游断供会传导到库存、服务能力和替代选择。
- 商品消费、服务使用和公共资源占用采用不同结算模型。

验收标准：

- 库存不会无来源自动恢复。
- 售出商品对应库存减少、现金流入和成本结转。
- 产能不足会导致排队、缺货、延期或替代。
- 服务消费能够追踪提供者、容量占用和交付结果。

### 2.4 收入、劳动与分配

- 已完成：居民合同保存合同类型、入职能力、实际时薪与每日排班；同一职位受容量限制，
  工资差异来自岗位、能力和可验证工时。
- 已完成：world tick 每日建立班次，并在次日使用成功的

  部分出勤只结算有效工时。
- 已完成：工资、奖学金、助学金与补贴通过组织预算和统一账本支付；预算不足形成
  `blocked` 支付记录。家庭支持使用授权外部流入，并保留外部支付方。
- 已完成：住宿、学习和交通等周期必要支出具有明确收款方、优先级和到期日，余额不足时

- 工资、兼职、奖学金、助学金和家庭支持。
- 学费、住宿、餐饮、交通和学习成本。
- 岗位需求、技能匹配、劳动时间和工资差异。
- 组织预算、项目经费和报销。
- 税费、补贴、罚款和公共转移支付。

验收标准：

- 每笔收入有支付方，每笔支出有接收方或明确销毁机制。

- 组织发薪、报销或补贴不会绕过预算。
- 初始禀赋和持续收入差异会形成可测量的不平等。

实施状态：已完成。

- 已完成：为每位居民建立预算档案和逐日预算快照，统一汇总账本现金、储蓄、

  所有现金与储蓄转移进入统一账本，并关联当前长期目标。
- 已完成：极端饥饿时仅允许使用已有储蓄支付基础食物，不允许透支、借款或隐式信用。
- 已完成：预算快照、储蓄转移和选择评估只读 API，幂等部署种子，以及
  `world-snapshot-v14-budget-choice` 快照恢复。

真实经济行为首先受到预算和时间约束：

```text
可支配资源
= 期初资产
+ 收入
+ 转移支付
+ 已启用的借款
- 必要支出
- 已到期偿债
- 储蓄
```

需要表达：

- 有限收入下的消费、学习、社交和储蓄权衡。
- 时间用于上课、兼职、休息或社交的机会成本。
- 当前消费与未来目标之间的跨期选择。
- 风险偏好、流动性不足和紧急支出。

信用功能未通过 `2.7` 验收前，借款和偿债项固定为零；基础储蓄只是统一账本中
个人活期账户与储蓄账户之间的可追踪转移，不隐含利息、透支或信用创造。

验收标准：

- Agent 不能在余额不足时无限消费。
- 放弃某项行动会释放时间或资金给其他行动。
- 短期选择会影响长期资产、健康、技能和机会。

### 2.6 供需、价格与市场摩擦

实施状态：已完成基础市场闭环。

- 已完成：商品与服务按提供者、地点和目录项目建立稳定市场机制，支持固定价、
  动态价、配给价和显式最高出价约束，不再接受 LLM 任意生成成交价。
- 已完成：动态价格按小时从基准价格、可核验成本、可售库存、过去 24 小时需求、
  成交量和环境资源压力计算，并保存状态指纹和中文解释；同一小时快照保持确定。
- 已完成：居民需求同时使用身体需要、稳定偏好、社会影响、需求弹性、可支配预算
  和最高支付意愿；价格过高、缺货或超过配额时会拒绝购买并搜索同地点替代品。
- 已完成：食堂基础商品和容量型服务使用每日配额；缺货、配给、替代、搜索成本和
  交易成本形成独立摩擦事件，市场不出清不会被自动改写为成功交易。
- 已完成：成交价格进入提供者收入，搜索和交易成本进入独立系统账户，库存、消费、
  需求信号和账本在同一结算中更新。
- 已完成：市场机制、价格、需求和摩擦只读 API，幂等部署种子，以及
  `world-snapshot-v15-market-pricing` 快照恢复。
- 后续边界：拍卖撮合、跨期预订、退款、违约和售后责任需要 `2.7` 的合同与信用事实，
  公共限价和补贴需要 `2.8` 的政策预算，不在本阶段绕过依赖提前模拟。

价格不能只是由 Agent 或 LLM 任意填写，应由可配置机制形成：

- 需求由需要、偏好、边际效用、预算、预期和社会影响共同决定。
- 供给由边际成本、固定成本、库存、产能和预期需求共同决定。
- 价格弹性、替代品和互补品。
- 固定价、竞价、议价、配给和动态定价。
- 搜索成本、交易成本和信息不对称。
- 品牌、信誉、质量预期和关系价格。
- 合同、预订、违约、退款和售后。

不要求所有市场都使用同一种“经济规律”。食堂套餐可以固定定价和配给，社团二手交易可以议价，稀缺实验资源可以按审批或排队分配。

验收标准：

- 价格变化可解释为供需、成本、规则或冲击结果。
- Agent 会因价格、收入和替代品改变需求。
- 市场不出清时会出现缺货、排队、积压或配给。
- 同一机制在相同状态和随机种子下可复现。

`2.9.1` 的补强交付：

- 将 `Information Item`、`Publication` 与 `Channel` 作为独立世界实体；传播从发布开始，而不是从

- 实现渠道的 Push/Pull 合约：Push 只产生可处理的投递或通知，Pull 必须由 `check_weather`、

- 以 `information_profile`、时间预算、注意力、权限、设备可得性、空间距离和关系强度决定接触
  概率或资格，保持确定性随机种子和可复现证据。
- 面向产品的“发送信息给 Agent”操作一律改为“选择信息如何进入世界”；定向邮件、私信和教师
  通知是合法渠道，直接写 Agent context 不是。

- 传播路径、暴露对象和信息变形可追踪。
- 同一规则对不同角色有不同可行性和后果。
- 信息和权力可以影响价格、机会、关系和组织决策。
- 外部同步、用户输入和编辑 Agent 都不能绕过 Publication/Channel/Exposure 链路直接改变任何
  Agent 的知识状态。

### 2.11 真实交互形态与社会接触补强

实施审计（2026-07-30）：部分完成，不能判定为完整。

当前 runtime 已能产生 `chat`、`club_activity`、`collaborate` 和 `conflict` 等社会行动，
并写入关系变化、社会互动、协作、竞争和承诺记录。传播渠道、组织提案与表决等基础设施
也已经存在。但是，当前自主交互仍以发起者的单步行动为主：接收者通常没有独立的感知、
接受、拒绝、反提议或离开决策，关系影响也可能只落在单侧。互动对象在同地点无人时还可能
退化为从全体居民中选择，因此现状只能证明“具备互动事件机制”，不能证明“具备完整的
双向社会交互”。

人与环境交互的基础比社会交互更完整：移动、观察、排队、消费、上课和休息会受到路径、
开放时间、容量、席位、库存、价格、预算、身体和天气约束，并结算资源与账本后果。但环境
目前主要表现为地点、数值和准入条件，尚未完整支持对具体物体的使用、占用、移动、损坏、
修复，以及一个 Agent 改变环境后其他 Agent 再感知和响应的连续因果过程。

本阶段使用以下统一交互分类，不能用其中一种代替其他类型：

| 交互形态 | 最小参与方 | 当前完成度 | 完整形态 |
| --- | --- | --- | --- |
| Agent 与自身 | Agent、身体、记忆和目标 | 基础具备 | 反思、恢复、策略调整及状态反馈 |
| Agent 与 Agent | 发起者、接收者 | 部分具备 | 双方独立决策、有界多轮、非对称后果 |
| Agent 与多人群体 | 三名以上 Agent 或临时小组 | 结构具备、过程不足 | 逐人参与、退出、联盟、共同决议和少数意见 |
| Agent 与组织/制度 | Agent、组织角色、规则和程序 | 机制具备、运行稀疏 | 申请、提案、审议、投票、执行、申诉和权力反馈 |
| Agent 与远程信息网络 | 发送者、接收者、渠道 | 机制具备、运行稀疏 | 延迟、失真、转述、澄清、拒收和网络扩散 |
| Agent 与环境实体 | Agent、物体、设施或空间资源 | 基础约束具备 | 使用、共享、占用、改造、损耗、维修和状态转移 |
| Agent 与环境过程 | Agent、天气、拥挤、噪音等过程 | 部分具备 | 持续暴露、累积影响、适应、规避和反向改变 |

目标统一交互协议：

```text
交互对象存在且具有可用能力（affordance）
→ 物理接触、通信、角色或资源资格
→ 发起者形成互动意图
→ 其他 Agent 独立响应，或环境实体按状态转换规则响应
→ 接受、拒绝、忽略、反提议、中断、离开、故障或升级
→ 有界的交流、协作、交易、冲突、使用或改造过程
→ 双方或多方产生可不对称的结果
→ 更新参与者状态与环境对象状态
→ 每名 Agent 分别更新记忆、信念、关系和承诺
→ 结果进入群体、组织、传播、外部性与新闻价值识别
```

按以下内部依赖推进：

- **2.11.1 接触资格与渠道证据**：面对面互动只能发生在可达的局部空间内，并满足距离、
  感知和共同停留时长要求；删除“同地点无人时从全体居民随机选择”的退化路径。远程互动
  必须显式记录渠道、发送与接收能力、传递延迟和未响应结果。
- **2.11.2 接收者自主决策**：接收者根据目标、注意力、身体状态、关系、信任、风险、
  制度条件和既有承诺独立决定响应，不能自动接受发起者的行动。
- **2.11.3 有界多轮与非对称后果**：支持问候与闲聊、请求与帮助、协商与交易、邀请与
  组队、冲突与修复、八卦与澄清等有限轮次互动。双方可以对同一次互动形成不同理解，
  并分别产生关系、记忆、信念、资源和情绪后果。
- **2.11.4 群体与制度交互**：支持三人以上小组、组织会议、提案、表决、共同承诺和
  多方冲突；阶段 `2.9` 的传播与制度服务必须消费真实互动或明确渠道事件，而不是自行
  制造已发生的社交事实。
- **2.11.5 环境实体与间接交互**：为门、座位、设备、商品、道路和公共设施等实体定义
  可用能力、占用方式、所有者、容量、耐久度、状态转换和恢复方式。支持使用、预约、共享、
  搬动、遗留、损坏、维修和改造；一个 Agent 造成的占用、短缺、噪音、污染或设施状态
  变化必须能被其他 Agent 感知并改变其后续选择。
- **2.11.6 频率校准与运行观测**：按共处机会、发起率、响应率、互惠率、重复互动对、
  网络聚类、传播深度和组织参与度校准，不用硬性“每人每天互动若干次”制造活跃假象。
  环境交互同时观察设施利用率、争用率、故障率、维修时长、外部性暴露和间接受影响人数。

实现约束：

- LLM 可以生成表达和解释，但不能绕过接触、响应和因果结算直接写入关系结果。
- 无 API key 时仍须由确定性策略完成响应和结果结算；相同状态与随机种子应可复现。
- `social_interaction_events` 继续作为审计锚点，并能关联互动会话、轮次、参与者状态、
  接触或渠道证据、结果和各参与者的后续记忆。
- 环境交互以 `world_action_executions`、空间资源、库存流水、账本和对象状态事件作为
  事实锚点，统一保存交互主体、目标类型、目标标识、能力、状态前后、占用区间、成本、
  失败原因和后续影响；不能只保存“使用了设施”的文本。
- 具体环境对象、共享资源和环境过程必须使用不同状态模型。座位占用不能退化为库存扣减，
  噪音暴露也不能退化为一次性的布尔事件。
- 互动必须允许拒绝、中断、延迟、误解和无响应。失败互动也是有效社会事实。
- 日记、生命历程和校园日报只能摘要已结算互动，不得补写不存在的对话或关系变化。

依赖关系：

- 阶段 `1E` 的局部感知和阶段 `2` 的空间接触证据是面对面互动的前置条件。
- 阶段 `1A-1D` 的空间真值、连续移动、准入容量和身体状态是环境实体交互的前置条件；
  阶段 `2.3` 的库存/服务和 `2.8` 的公共服务/外部性提供共享资源与间接影响账本。
- 阶段 `2.9` 的信息传播、制度程序和组织权力消费互动结果，并向后续互动提供信念、
  信任和制度条件。
- 阶段 `3.1.2-3.1.4` 的学习、规范涌现和制度演化必须使用双向互动证据。`2.11`
  因此是宣称社会涌现完整之前必须完成的跨阶段补强项，不要求回滚已经完成的阶段 3 代码。

验收标准：

- 不存在缺少接触证据的远距离面对面互动；远程互动均有明确通信渠道。
- 每次自主互动至少保存发起者和接收者状态；忽略或无响应必须被显式记录。
- 接收者的选择能够改变互动是否发生、持续多久以及最终结果。
- 关系变化支持双向且不对称，能追溯到具体互动、参与者判断和结果。
- 支持三人以上互动，并能从轨迹、接触、会话和结果记录重建关键群体事件。
- 受控测试能够实际产生信息传递、信息暴露、组织提案和表决记录。
- Agent 只能对当时可达且状态允许的环境实体执行其支持的操作，失败必须具有结构化原因。
- 共享实体支持独占、并发、预约、排队和释放；多个 Agent 争用时不存在静默重复占用。
- Agent 对环境造成的改变能够持续存在，被其他 Agent 感知，并通过选择或状态产生间接
  后果；该因果链可以从对象状态和事件记录重建。
- 设备损坏、资源耗尽、噪音或拥挤等环境过程可以通过维护、补货、疏散、规避或制度行动
  得到响应，而不是由下一次 tick 无来源地自动恢复。
- 相同初始状态、配置和随机种子产生可复现的互动序列与统计口径。

## 阶段 3：适应、开放世界与长期演化

阶段 3 先让 Agent 能够在约束中尝试、违反、学习、模仿并改变规则，再证明世界能够
处理内部定义、可复现的变化和冲击，最后才允许真实世界数据映射到同一事件协议。
外部数据不能绕过内部机制直接改写 Agent、制度规则或宏观指标。

阶段 3 不再把“自然社会环境”理解为继续增加固定条件。阶段 0-2 建立的空间、资源、
账本、组织、传播、程序和证据机制在本阶段被划分为三层：

- **不可变因果不变量**：因果顺序、时间单调性、空间连通性、库存守恒、复式记账和
  已发生历史不可覆盖。这些约束不能被 Agent 投票或叙事改写。
- **可违反的现实约束**：围栏、门锁、容量、开放时间、身份权限、预算、合同和组织命令。
  它们改变可行路径、成本、风险、成功概率、被发现概率与后果，但原则上不直接删除行动。
- **可演化的社会规则**：惯例、非正式规范、组织章程、价格机制、审批程序、处罚尺度和
  公共政策。它们可以由重复行为、冲突、协商、模仿、提案、投票和政策反馈形成或改变。

- 每次约束评估、越界尝试、学习更新、规范变化和正式规则变更都必须保存世界分支、

### 3.1 约束软化、适应学习与规则演化

#### 3.1.1 约束软化与越界行动

将当前“条件不满足即拒绝”拆成彼此独立的现实维度：

```text
物理可达性：是否存在可执行路径，障碍是否能够攀越、破坏或绕过
制度许可：规则是否允许，谁有权授权、豁免或追认
服务可用性：地点可进入不等于服务仍在运行
容量压力：拥挤改变等待、舒适度、安全性和成功率
执法与监测：违规是否被观察、识别、记录和处理
后果与外部性：受伤、损耗、处罚、信誉、关系和他人福利变化
```

例如操场“关闭”默认只关闭正式服务或撤销制度许可。只要物理上仍可进入，Agent 仍可以
翻越、尾随、借用凭证、请求豁免或承担风险进入；只有不可穿越的真实物理障碍才产生硬性
不可达。容量达到名义上限后也不应自动成为抽象墙，而应进入排队、拥挤、配给、协商、
插队、超载或执法分支。

每次行动候选至少产生以下评估结果：

```text
physically_possible
officially_permitted
service_available
expected_time / expected_cost
success_probability
detection_probability
harm_probability
expected_sanction
affected_agents / affected_resources
constraint_rule_versions
```

验收标准：

- 关闭、权限不足和名义容量不再普遍等同于动作不存在。
- 同一越界行动因身体能力、资源、关系、角色、监测强度和空间结构产生不同结果。
- Agent 可以成功违规、失败、未被发现、事后被发现、被豁免或通过申诉改变后果。
- 物理进入、制度许可、服务获得和最终后果分别记录，不能压缩成单个 `allowed` 布尔值。
- 越界不会凭叙事获得资源；库存、账户、身体和空间结果仍经过统一因果执行器。

#### 3.1.2 记忆、学习与策略变化

学习以“事实经历 → 主观观察 → 记忆与信念 → 策略更新 → 后续行动”为闭环。当前并行的
行动日志、个人记忆、空间记忆、信息信念和日记需要通过共同的事件引用连接，而不是继续
形成互不影响的阅读数据。

区分：

```text
短期状态变化：疲劳、情绪和注意力
中期策略变化：回避拥挤、改变消费、路线、合作对象或违规方式
长期能力变化：技能、习惯、信誉、风险偏好和制度预期
```

- 记忆必须保留来源事件、当时可见信息、主观解释、置信度、情绪显著性和后续修正。
- 提取频率、时间衰减、相似经历、他人反馈和反事实结果共同影响记忆权重。
- 重复经历可以被归纳为技能、习惯或预期；长期不用、环境变化和反例会造成衰退或修正。
- 学习更新必须作用于可观察的成本、成功率、候选行动排序或目标优先级，不能只生成文本。
- 日记是 Agent 对经历的主观叙述，可以引用学习证据，但不能反向制造经历或提高重要性。

验收标准：

- Agent 会根据成功、失败、未被发现、处罚、他人反馈和观察到的他人结果调整策略。
- 技能可随实践增长或长期不用而衰退，策略会随环境和规则版本变化而失效或迁移。
- 相同事实可以因观察范围、既有信念和记忆不同而产生不同学习结果。
- 任意策略变化可以追溯到经历、观察、记忆、反馈和更新规则。
- 通用记忆与空间记忆都会实际进入 world runtime 决策，而不只用于人物页面展示。

#### 3.1.3 非正式规范涌现

规范不是预先写入的统一偏好，而是群体对重复行为及其后果形成的共享预期。候选规范至少
从以下证据中产生：

- 行为在特定群体、地点和情境中的重复率与稳定性。
- 观察者的赞同、反对、模仿、提醒、八卦、排斥和非正式奖惩。
- 行为给参与者、旁观者、组织、资源和公共福利造成的实际结果。
- Agent 对“别人通常怎么做”和“别人期待我怎么做”的信念分布。
- 反例、代际变化、群体边界与不同规范之间的竞争。

候选规范应经历 `emerging → contested → established → weakening → dissolved` 等可逆状态，
并明确适用群体、空间、情境、支持率、反对率、观察覆盖、置信度和证据窗口。多数人重复
同一行为不自动等于规范；必须同时出现共享预期或社会反馈。

验收标准：

- 未预置规范名称时，系统也能从行为和社会反馈识别候选规范。
- 不同宿舍、组织、角色或关系网络可以形成相互冲突的局部规范。
- Agent 对规范的服从、策略性表演、隐藏违反和公开挑战具有不同动机与后果。
- 规范可以通过模仿和传播扩散，也可以因反例、冲突、人员流动和环境变化衰退。
- 任意规范状态变化可下钻到行为、观察、传播、反馈和群体信念证据。

#### 3.1.4 制度演化与规则创造

非正式规范不会自动升级为正式规则。制度化必须经过可识别的政治与组织过程：

```text
问题或规范进入议程
→ 利益相关者提出规则方案
→ 支持、反对、游说、协商与修订
→ 授权主体按章程投票、决定或试点
→ 发布带版本和生效范围的正式规则
→ 执行、绕行、申诉与政策反馈
→ 保留、修订、废止或被新规则替代
```

- 提案必须说明触发证据、目标、适用对象、执行主体、预算、监测方式、处罚或激励、
  生效时间、复核时间和废止条件。
- 权力、信任和资源影响议程与通过概率，但不能替代组织权限和程序事实。
- 正式规则以版本化机制参数进入因果执行，不能依赖修改 prompt 或覆盖历史记录。
- 第一版规则创造通过受控的规则原语、参数、适用范围和组合关系完成，不允许 LLM 直接
  生成或执行任意代码；超出机制目录的提案可以被讨论和记录，但在实现对应机制前不能生效。
- Agent 可以创造新的惯例、组织规则和政策组合，但不能改写物理与账本不变量。
- 规则效果按目标结果、分配影响、规避行为、执行成本、外部性和制度信任持续反馈。

验收标准：

- 至少一种未在初始世界配置中启用的正式规则能由 Agent 提案并依法生效。
- 能区分参数调整、已有规则原语的新组合和需要新增底层能力的制度诉求，不能把改名或
  prompt 变化算作新规则。
- 同一候选规范可能被制度化、被否决、被少数权力主体扭曲，或长期保持非正式状态。
- 规则执行会产生服从、规避、公开冲突、申诉和替代制度，而不是全体即时服从。
- 规则修订和废止不会覆盖历史；任意时点可重建当时有效的规则集合。
- 相同快照可分叉为不同治理决策，并比较行为、经济、关系、福利和信任后果。

### 3.2 内生异常、冲击与恢复

先使用配置化、可重放的内部冲击验证世界反应：

- 暴雨、停电、故障、断供和安全事件。
- 考试延期、公共卫生和校园管理事件。
- 就业、价格、收入和政策冲击。
- 恢复资源、应急决策、替代服务和次生影响。

验收标准：

- 冲击改变物理可行性、行动成本、风险、供需和组织决策；制度限制仍遵循 `3.1.1`
  的许可、越界和后果模型。
- 系统记录冲击来源、范围、持续时间和恢复过程。
- 同一冲击对不同群体产生异质后果。
- 相同快照、配置和随机种子可以复现冲击传播与恢复。

### 3.3 人口、角色与成员流动

- 新生、毕业、转专业、休学和退学。
- 交换生、教师调动和岗位变化。
- 社团招新、退出、宿舍调整和组织换届。
- 家庭支持、城市迁移和外部机会变化。

验收标准：

- 长期世界的人口结构不会永久固定。
- 人口变化会影响资源需求、组织记忆和关系网络。
- 离开世界的 Agent 保留可审计历史，但不继续行动。

### 3.4 真实世界数据接入与事件映射

本节的表结构、事件语义、运行模式和安全边界以
`EXTERNAL_WORLD_DATA_DESIGN.md` 为详细技术契约。外部 API 只提供观测，
不能被视为世界真相，也不能在 world tick 中直接请求或直接修改世界状态。

按因果价值排序接入：

- 天气、恶劣天气预警、校园官方通知和设施状态。
- 城市交通、周边可达性、基础价格、供给和就业数据。
- 公共卫生、政策、公共新闻和行业变化。
- 社会趋势主要进入认知传播；高噪声社交媒体仅在来源授权、隐私、
  操纵风险和事实核验机制成熟后受控接入，不属于第一版来源。

外部数据必须分为不可变原始观测、标准化事件和校园影响，不能只保存摘要。
原始观测至少保留来源、来源记录标识、内容哈希、原始 payload、抓取批次、
解析版本和校验结果。标准化事件统一使用以下核心字段：

```text
source_id
raw_observation_id
source_record_id
occurred_at
published_at
observed_at
ingested_at
effective_from / effective_to
expires_at
geo_scope / campus_scope
affected_spaces / affected_roles / affected_organizations
affected_economic_sectors
confidence
verification_state
transform_version
correction_of / replaces_event_id
```

每个事件允许产生彼此独立、均可追踪的两条链路：

- **客观影响链**：经 `external_event_impacts`、版本化确定性规则和
  `world_event_stream` 改变空间、交通、供给、价格、制度或其他客观状态。
- **认知传播链**：经 `external_exposures` 通过媒体、组织、现场观察和关系网络
  传播，Agent 可以相信、质疑、忽略或继续转发。

外部事实进入认知世界时，必须先成为可定位的来源主张和发布物，而不是同步任务选择一批 Agent
直接投影：

```text
External Observation → Source Claim → Information Item → World Publication
→ Channel / media institution → Access / Exposure / Attention
→ Interpretation / Belief / Memory → Action
```

例如 RSS 先进入世界内的新闻网关或编辑机构，天气预警先进入天气服务、官方 App 或广播；编辑
Agent 可以决定是否转载、如何标注来源和发布到哪个频道，但不能把“已抓到的新闻”直接变成居民
已知事实。客观天气、道路封闭等影响链可独立生效；**客观影响发生不等于任何 Agent 已知原因。**

完整链路是：

```text
外部来源
→ 不可变原始观测
→ 校验来源、授权、时效、单位和可信度
→ 去重、冲突、更正与标准化
→ 映射为阶段 3.2 已验证的事件或冲击
→ 候选影响通过版本化规则进入 world_event_stream
→ 客观状态变化与 Agent 渠道暴露分别发生
→ Agent 形成不同理解、行动与关系变化
```

实施子序列：

- **3.4.1 可审计接入层**：来源注册、原始观测、同步运行与现有接口兼容。
- **3.4.2 事件标准化**：事件目录、时间与范围语义、去重、冲突、更正和撤回。
- **3.4.3 快照、回放与认知传播**：`live`、`snapshot`、`replay`、
  `synthetic` 模式、Publication/Channel 版本，以及可追踪 Agent 暴露、注意和理解。
- **3.4.4 环境及经济因果映射**：候选影响、规则校验、幂等应用、撤销条件和状态对账。
- **3.4.5 治理、研究与运行验收**：许可、保留期、权限、降级、实验元数据与导出。

验收标准：

- 任意已应用影响都能追溯到原始观测、标准事件、转换版本、影响规则和世界事件。
- 删除或断开外部接口后，world runtime 仍可推进，并能使用冻结快照复现实验。
- 同一外部事实不会因重复同步被重复应用。
- 多来源冲突、高影响低置信事件不会自动修改关键状态。
- 来源更正、替代或撤回不会覆盖历史，并能形成新的认知传播。
- 客观环境变化与 Agent 主观认知可以分别查询；Agent 不会因事件已入库而自动知晓。
- 外部同步不会直接创建 Agent 信念、记忆或 context；每一条认知后果都能还原来源、发布物、
  渠道、访问资格、暴露、注意和解释。
- 外部数据只通过标准事件、传播和版本化因果规则影响世界。
- 来源失败、数据过期或整体不可用时暴露 `stale` 或
  `external_data_degraded`，且不伪造最新数据。
- 数据授权、敏感等级、可信度和过期策略在应用前完成检查。

### 3.5 长期轨迹与路径依赖

轨迹、账户、关系、感知和行动事实从阶段 1 开始持续记录；本阶段负责跨周期聚合、解释和路径依赖分析，而不是到此时才开始保存历史。

- 习惯、信誉、社会位置和目标转变。
- 高光、失败、关系修复和经济积累。
- 课程、项目、就业、社团和毕业阶段。
- 非正式规范的形成、竞争与衰退，以及正式规则的提案、修订和制度谱系。
- 初始禀赋、早期事件与后续机会之间的路径依赖。

验收标准：

- 生命历程呈现阶段、转折、原因和后果。
- 长期目标被环境、关系、制度和经济条件持续塑形。
- Agent 不会每天重置人格、策略和资源历史。
- 能区分个体记忆、群体规范和正式制度历史，并追踪三者之间的因果引用。

### 3.6 内生世界与涌现行为重构

本阶段是下一版本的核心优化。它不追求让世界“没有规则”，而是把规则从高层剧本下沉为
自然世界需要的底层不变量和可组合过程。系统只定义物理、守恒、感知、身体、资源、对象、
组织权限和风险后果；具体社会行为、活动名称、新闻价值、规范和制度变化必须从 Agent
行动、环境状态和多方反馈中产生。

#### 3.6.1 去模板化环境生成

现有按时间直接推导拥挤、情绪、消费指数和资源压力的模板，只能作为缺数据时的初始化
或先验，不应在 runtime 中覆盖真实状态。环境状态必须优先来自：

- Agent 实际位置、移动、停留、排队、占用和共同活动。
- 商品、服务、设施、库存、订单、维修、损耗和恢复。
- 天气、光照、噪声、交通、政策、冲击和外部数据标准事件。
- 组织排班、预算、人员、服务能力和执行失败。
- 历史趋势、季节性和随机扰动，但这些只能作为可解释的过程输入，不能替代事实。

验收标准：

- 没有人去食堂时，食堂不会仅因饭点自动出现高拥挤事实。
- 拥挤、资源压力、价格压力和公共情绪都能下钻到 Agent、对象、服务、冲击或外部事件。
- 模板先验与实际观测冲突时，实际观测优先，并记录校正事件。

#### 3.6.2 原子行动与 affordance 发现

固定语义行动菜单应拆为可组合原子行动。Agent 不应只能选择 `chat`、`consume`、
`club_activity` 这类标签，而应根据局部环境发现可行动机会：

```text
move / wait / observe / approach / signal / speak / listen / invite / accept / refuse
use / occupy / release / carry / exchange / give / request / repair / damage / bypass
coordinate / follow / lead / join / leave / record / report / propose / vote / appeal
```

这些原子行动由身体状态、空间距离、对象 affordance、权限、资源、风险、关系和记忆共同
决定可行性。高层活动只作为后验识别结果，例如：

```text
多人在操场接近同一运动设施
→ 占用场地与器材
→ 互相传递、等待、协作、竞争、休息
→ 产生身体消耗、关系变化、围观、冲突或愉悦记忆
→ 后验识别为“一起打球”
```

验收标准：

- 新活动不需要新增一个同名 action 才能发生。
- 同一组原子行动可以在不同地点被识别为吃饭、排练、维修、旅行、交易、冲突或集会。
- 活动识别器只消费证据，不反向制造轨迹、关系、库存或记忆。

#### 3.6.2A 软约束多路径决策模型

真实世界中的身体、时间、空间、经济和制度约束不应默认写成单一路径硬规则。硬规则只保留
给不可突破的不变量，例如物理不可达、账本守恒、死亡、权限边界、历史不可覆盖和数据库
一致性。其余多数约束应作为软约束进入行动候选分布、成本、风险、成功率和长期后果。

例如饥饿不应被实现为：

```text
if hunger > 85:
    action = consume
```

也不应只被实现为：

```text
if hunger > 85:
    reject reflect / observe
```

更真实的模型应是：

```text
hunger 提高食物相关行动权重
fatigue 提高睡眠、拖延和放弃权重
stress 改变冲突、求助、逃避和失误概率
money、库存、地点、开放时间和关系改变可行性与成本
personality、memory、goal 和 social_norm 改变忍耐、求助、违规或自律倾向
```

同一名极饿 Agent 可以去食堂、买零食、向朋友求助、赊账、忍着继续学习、睡觉逃避、违规
拿取公共资源、情绪失控、健康恶化，极端情况下也可以崩溃或死亡。系统不应提前指定唯一
“正确反应”，而应让这些路径在共同的世界约束下竞争。

工程上采用四层分工：

1. 世界机制计算事实约束：身体、资源、空间、时间、库存、账本、关系和制度状态。
2. 结构化策略生成候选分布：每个行动带有成本、风险、成功率、证据需求和后果。
3. LLM 只在必要时进行主观裁决、动机解释、对话和语义长尾处理，不能绕过事实结算。
4. 结果进入记忆、策略状态和因果证据，影响后续 tick 的选择，而不是只留下失败文本。

验收标准：

- `hunger=100` 不会让 Agent 永久重复 `reflect/observe` 失败；但也不会强制所有人立刻
  执行同一个 `consume` 动作。
- 至少支持吃饭、购买、借助、忍耐、睡眠逃避、求助、违规、崩溃等多条可解释路径。
- 相同身体状态在不同人格、资源、地点、时间和关系条件下产生不同选择。
- 行动失败会改变后续候选权重，并能追溯到失败事件、记忆、策略更新和世界状态。
- 所有资源、身体和账本后果仍由统一因果执行器结算，不能由 LLM 直接写入。

#### 3.6.3 接收者自主与多方社会过程

社会交互不能由发起者一次性决定。面对面、远程、组织和环境介导交互都应形成可暂停、
可中断、可失败、可升级的 session：

- 发起者提出意图或信号。
- 潜在接收者必须实际可感知，或通过可信渠道收到信息。
- 每名接收者基于目标、注意力、身体、关系、信任、风险和记忆独立响应。
- 多人可以加入、退出、旁观、误解、转述、阻止、调解或形成子群体。
- 后果按参与者分别结算，允许非对称记忆和关系变化。

验收标准：

- 支持双人、多人的吃饭、打球、学习、旅行、会议、争吵、协作和围观。
- 同一互动里可以同时出现参与者、旁观者、受影响者和后续传播者。
- 群体事件必须能追溯到实际接触、会话、共享对象、共同路线或组织程序证据。

#### 3.6.4 自生长环境实体与过程

环境必须像真实世界一样持续开放变化。空间不只是节点和容量，还应包含对象、材料、服务、
生态和维护过程：

- 可操作对象：门、围栏、座位、桌椅、器材、商品、垃圾、公告、设备、车辆和钥匙。
- 对象状态：位置、所有权、占用、耐久、清洁度、故障、库存、温度、噪声和可见性。
- 自然过程：昼夜、天气、积水、磨损、拥挤扩散、噪声传播、疲劳恢复和食品变质。
- 人工过程：补货、清洁、维修、安保巡查、排班、审批、预算和公共服务。
- 间接影响：占座、损坏、遗留物、噪声、价格上涨、排队变长、谣言扩散和服务中断。

验收标准：

- 对象状态不会在 tick 间无理由恢复。
- 设施故障、短缺和污染等状态需要资源、时间、组织或 Agent 行动才能恢复。
- Agent 可以通过改变环境对象间接影响未见面的其他 Agent。

#### 3.6.5 经济与制度的内生规律

经济规律不应是死规则，也不应完全任意。系统应固定守恒、预算、库存、生产容量、信用
承诺和风险暴露等底层约束，让价格、工资、配给、补贴、黑市、互助、节约和投机从供需、
组织策略、Agent 预期和制度反馈中变化。

制度也应如此：物理世界不能被投票改写，但开放时间、处罚、预算分配、预约制度、社团
章程、服务优先级和信息发布机制可以由问题、冲突、提案、协商、执行和反馈逐步演化。

验收标准：

- 价格和服务质量变化能追溯到库存、成本、需求、预算、政策和组织决策。
- 经济适应可能产生节约、替代、互助、违约、套利、囤积或非正式交换。
- 新制度必须通过组织或群体过程生效，并接受执行成本、规避行为和信任反馈检验。

#### 3.6.5A 微观—群体—制度跨尺度桥

宏观社会现象不能只是底层事件的平均值，也不能由系统反向宣布。系统需要保存从微观行动
到群体模式、组织响应和制度结果的机制路径。跨尺度桥用于回答：

```text
哪些个体行动形成了群体模式？
中间经过了哪些空间、关系、信息、资源或组织状态？
覆盖率和数据质量是否足以支持解释？
是否存在共同外部冲击、重复根事件或替代解释？
宏观指标是否能下钻回微观来源？
```

第一版优先实现三条桥：

- Agent 移动、时间预算和空间选择 → 空间拥挤、等待、放弃与服务压力。
- 信息接触、关系信任和重复暴露 → 群体传播、信念分布与编辑 Agent 选题。
- 个体交易、库存和预算约束 → 价格压力、资源短缺与组织响应。

跨尺度桥必须保存来源单位、聚合窗口、聚合规则、中间机制、覆盖率、替代解释和规则版本。
中间机制缺失时，只能报告“不完整解释”；群体或宏观指标不能反向制造 Agent 事实、轨迹、
交易、记忆或信念。

验收标准：

- 宏观指标可以下钻到参与 Agent、来源事件、交易、传播或空间轨迹。
- 同一根事件不会被重复聚合。
- 不同群体可以在同一宏观现象中拥有不同机制路径。
- 聚合窗口、规则版本和数据覆盖率进入研究导出。
- 分支间比较必须检查观察单位、规则版本、实际暴露和数据质量是否可比。

#### 3.6.6 后验叙事、新闻与可解释性

校园日报、人物介绍、生命历程和研究报表只能作为事实层的解释器。它们应从底层证据中
识别新闻价值，而不是凭模板制造事件：

- 稀有行为、异常路线、异常聚集、失败恢复、价格突变、关系突变、规范冲突和制度变化。
- 多人共同活动、持续协作、公开争议、隐性影响和环境连锁反应。
- 个体生命转折、长期策略变化、社会位置变化和路径依赖。

验收标准：

- 每篇新闻、关键经历和人物变化都能回链到原子行动、对象状态、互动 session、账本、
  记忆、规范或制度事件。
- 没有底层证据时，日报可以说“今日无显著事件”，不能生成看似真实的故事。
- 新闻价值排序由异常度、影响范围、持续性、冲突性、新颖性、关系变化和证据置信度共同决定。

#### 3.6.7 迁移策略

新世界按以下顺序建立：

```text
停止环境模板覆盖和伪群体事件
→ 引入环境实体、对象状态和过程账本
→ 将固定行动菜单映射为原子行动组合
→ 将双人和多人互动改为 session
→ 将生产、恢复、价格和服务改为 Agent/组织驱动
→ 泛化学习、规范和制度原语
→ 最后升级日报、人物页和生命历程解释器
```

每一步都必须同步替换前端与测试；不得保留旧 API 的兼容读取层。新增机制必须拥有
确定性回放、快照恢复、证据下钻和失败保留；不能用 LLM 文案绕过物理、账本和对象状态。

## 阶段 4：研究、校准与治理

阶段 4 负责把已运行的机制升级为可信研究能力，但研究元数据、失败保留、数据授权、隐私和审计不能等到阶段 4 才开始。

### 贯穿阶段 1-3 的治理与测量门槛

- 每次运行记录配置、代码版本、模型版本、随机种子和外部数据快照。
- 失败运行、规则冲突、账本异常和数据缺失不得静默删除。
- 真实人物、敏感属性、心理状态和真实校园复刻需要明确授权与用途限制。
- Prompt、行为日志、轨迹、关系和外部数据执行最小必要采集与脱敏。
- 研究机构、世界分支和导出任务具有访问隔离与审计记录。
- 禁止将模拟推断直接用于现实个体的重要决策。
- 每个 `2.x` 和 `3.x` 子阶段在实现机制时同步记录输入、暴露、状态变化、
  失败原因和结果指标，并定义单位、聚合窗口和版本。
- 阶段 4.1 统一、审查和固化指标体系，但不得依赖事后从叙事文本补造
  阶段 2-3 未记录的机制证据。

在进入阶段 3.4 的真实世界数据接入前，至少必须完成数据来源、授权、敏感等级、允许用途、保留期限和删除策略检查。

### 4.1 测量体系与证据完整性

先定义研究问题、观察单位和统计口径，再运行校准或实验。

- 微观指标：行动数量、时间分配、消费结构、社交频率和计划完成率。
- 宏观指标：客流曲线、价格分布、交易量、网络密度、传播速度和资源分配。
- 机制指标：结果是否由正确机制产生，而不是由 LLM 或日报直接编排。
- 演化指标：越界率、发现与处罚率、策略迁移、规范支持与分歧、制度提案和规则存续时间。
- 暴露指标：Agent 是否实际接触空间、政策、消息或实验干预。
- 数据质量指标：缺失、延迟、重复、异常和版本覆盖率。

验收标准：

- 每个指标具有定义、单位、聚合窗口、数据来源和误差说明。
- 指标可以下钻到底层状态、事件、轨迹、账本或感知记录。
- 同一实验的不同运行使用一致统计口径。
- 缺少必要证据时明确返回“不可判断”，不生成确定性结论。

### 4.2 校准与有效性验证

可使用：

- 客流、课表、空间使用和食堂高峰数据。
- 价格、消费、岗位、奖助学金和预算数据。
- 问卷、访谈、社交网络统计和作息研究。
- 真实事件案例与领域专家评审。

验收标准：

- 校准数据与验证数据分离。
- 参数拟合不能使用最终验证样本。
- 同时检查微观、宏观和机制有效性。
- 规则改变后自动运行回归与基础敏感性检查。

### 4.3 实验与反事实控制

- 对照组、实验组和随机分组。
- 单变量、多因素和剂量实验。
- 干预开始时间、结束时间、对象和实际暴露。
- A/B 世界、重复运行和反事实分叉。

验收标准：

- 可从相同快照和随机种子分叉世界。
- 可证明两个世界除目标变量外保持一致。
- 记录 Agent 是否真正接触干预。
- 支持多次运行后的统计比较，而非只展示一个故事。

### 4.4 敏感性、稳健性与失败分析

- 参数扰动和随机种子变化。
- LLM 可用与不可用模式对照。
- 极端值、边界条件和压力测试。
- 死锁、数据缺失、规则冲突和账本不平衡。

验收标准：

- 关键结论不会只在单一随机种子下成立。
- 失败运行被保留并分类，不被静默删除。
- 研究报告明确机制假设和不确定性。

### 4.5 可复现报告、治理复核与结论边界

- 导出实验配置、数据字典、版本、排除规则和分析脚本摘要。
- 报告区分模拟事实、机制解释、统计关联和现实推论。
- 记录失败运行、异常处理、人工干预和模型不可用模式。
- 高风险实验执行伦理复核、用途限制和访问审计。
- 支持由快照、分支和随机种子重建报告中的关键结果。

验收标准：

- 独立运行可以根据导出元数据复现实验设置和主要指标。
- 报告不会把模拟相关性表述为现实因果结论。
- 导出数据遵循最小必要原则并附带授权与用途元数据。
- 高风险实验具有显式审批、审计记录和撤销机制。

## 对反馈的采纳与优先级调整

本次路线图接受了反馈中的主要判断，并作出以下结构变化：

- 将环境生成、统一因果执行、快照分叉和多尺度更新前移为阶段 0。
- 将有限可观测性从后期能力前移到阶段 1，避免决策系统继续依赖全局真相。
- 将个体异质性从人物描述升级为成本、能力、机会和成功率差异。
- 将资源稀缺扩展为能够核算的经济闭环，而不是继续增加零散资源字段。
- 将统一账本和组织主体前移到阶段 2 起点，使生产、收入、预算和政策拥有可对账基础与责任主体。
- 将学习、人口流动、外部世界、校准、反事实和伦理纳入正式阶段。
- 将约束从普遍硬拒绝拆分为物理可达性、制度许可、服务、容量、监测、风险和后果，
  使 Agent 可以尝试越界并承担可追踪结果。
- 将个体学习扩展为非正式规范涌现、正式制度演化和版本化规则创造，明确区分不可变
  因果不变量与可演化社会规则。
- 将内部可复现冲击前置于真实世界数据接入，外部数据不得绕过标准事件和因果规则。
- 将数据授权、隐私、失败保留和审计设为阶段 1-3 的持续门槛，而不是阶段 4 的收尾工作。
- 将“能否出现某种现象”的验收升级为微观、宏观和机制有效性验证。

路线图没有把所有能力都提前到第一阶段。经济、传播和组织机制仍依赖阶段 0 的因果与状态底座；复杂金融、外部市场和研究治理也不应阻塞最小校园生活闭环。

### 当前支线：真实地理导入 MVP

当前开发提前启动 `3.4A`，目标不是一次完成完整 Cross-World 架构，而是先验证真实地理数据能否安全进入现有空间真值层。

MVP 边界：

- 使用 OpenStreetMap / Overpass 导出的 GeoJSON 作为首选开放数据源。
- 将建筑、道路、水体、绿地、铁路、水系、POI 和地形点翻译为 `spatial_nodes` / `spatial_edges`。
- 以 `world_key`、原始 OSM tags、几何 footprint/path geometry 和本地坐标转换结果保留来源线索。
- 先在本地 SQLite dry run 和小范围真实片区验证，不阻塞阶段 3.6 与 Roadmap 2 的观察层开发。
- 中国校园数据优先用 OSM 小范围 bbox 验证；高德/百度主要用于搜索、展示和人工校验，不作为批量几何抽取源。

MVP 之后再补齐 R3 已定义的完整翻译层：导入批次、来源引用、geometry 表、坐标转换版本、楼层层级、访问规则和服务点校正。

阶段 1 先建立空间真值和可执行移动，再依次加入准入、身体、信息和个体差异，避免后续机制继续依赖地点标签或全局数据库真相。

阶段 2 先保证账户守恒和组织责任，再让资源、价格、关系和权力形成社会结构。

阶段 3 先让约束可以被尝试和违反，再让经历产生学习、学习汇聚为规范、规范经过政治与
组织程序改变正式规则；随后验证冲击恢复、人口流动、外部数据和长期轨迹。下一版本的
`3.6` 不再继续堆固定行为，而是把高层行为、活动、新闻和制度意义改为从原子行动、
环境对象、多方互动和连续反馈中涌现。

治理门槛贯穿阶段 1-3；阶段 4 让系统从“能够产生故事”升级为“能够支持可信研究”。

## 经济系统的最小可行闭环

经济系统不应一次实现全部金融和市场机制。建议先完成一个能够对账的最小闭环：

```text
1. 统一账户与交易账本
2. 经济与组织主体、权限和预算责任
3. 商品/服务目录、生产和库存来源
4. 固定周期收入、劳动报酬与必要支出
5. Agent 预算约束、机会成本和替代选择
6. 可配置价格规则与缺货/配给
7. 公共预算、补贴、收费与外部性
8. 资金、库存、分配和宏观指标对账
```

第一版先验证“钱从哪里来、到哪里去，商品如何产生和消失，价格为什么变化”。在账本闭环稳定后，再加入劳动市场、信用、合同、外部市场和复杂政策。

## 防止伪真实感

以下现象不能单独证明系统真实：

- Agent 会谈论钱，但余额不受影响。
- 商户会涨价，但没有成本或需求变化。
- 日报报道缺货，但库存没有减少。
- 所有人同时知道同一条消息。
- 组织有名称，但没有预算、规则和决策过程。
- 出现宏观曲线，但不能追溯到底层事件。
- LLM 给出合理解释，但相同状态无法复现。

每项“真实感”能力都必须同时具备：

```text
结构化状态
+ 可执行规则
+ 可追踪事件
+ 对后续行动的影响
+ 可校准指标
```

## World2 架构优化方向（2026-08-07）

当前架构足以支撑 World2 第一阶段和第二阶段早期开发，但距离可扩展世界模型仍需完成一次事实层与运行时收敛。后续优化不以减少文件行数为唯一目标，而以可复现、可组合、可校准为验收标准。

### 优化优先级

1. **收敛应用入口**：`main.py` 只保留应用装配、生命周期、依赖注入和兼容桥接；领域规则迁移到 runtime/service/repository。
2. **统一世界事实层**：明确 `WorldState`、`WorldEvent`、`ActionExecution` 的写入边界，逐步减少旧表、兼容投影和重复事件源。
3. **组合式 tick 管线**：将时间、环境、Agent、社会、经济、外部世界和多尺度更新拆成可排序、可重试、可观测的机制阶段。
4. **真实空间闭环**：让导入的建筑、道路、绿地、水体和 POI 参与路径规划、容量、准入、服务和 Agent 行为选择，而不仅用于展示。
5. **规则与模型分工**：LLM 负责意图、解释和有限信息下的决策；规则引擎负责前置条件、资源结算、事件写入和可复现结果。
6. **研究与运行隔离**：运行时事实、派生指标、校准观测和实验快照分层，确保实验可回放、指标可追溯。
7. **部署与并发收敛**：本地 SQLite 作为开发模式，线上 PostgreSQL 作为运行模式；明确 tick 锁、任务队列和多实例一致性策略。
8. **前端领域化**：地图、Agent、事件流、观察器和研究面板逐步拆分，避免单文件前端继续成为演进瓶颈。

### 阶段性验收

- `main.py` 不再包含新的领域业务实现。
- 每个领域至少具备“状态 → 规则 → 事件 → 反馈 → 指标”闭环。
- 同一快照、配置、随机种子和事件游标能够得到可解释且可复现的结果。
- 真实空间导入数据能够改变至少一种移动、准入或服务行为。
- 核心 tick、快照恢复、分支切换和 schema 安全测试持续通过。
