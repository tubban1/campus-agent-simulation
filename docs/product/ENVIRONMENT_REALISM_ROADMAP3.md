## 1. 文档定位

本文件是 [ENVIRONMENT_REALISM_ROADMAP.md](ENVIRONMENT_REALISM_ROADMAP.md) 和
[ENVIRONMENT_REALISM_ROADMAP2.md](ENVIRONMENT_REALISM_ROADMAP2.md) 的第三份补充，不替代前两者，
也不重新定义它们已经确立的事实边界、资源守恒、权限隔离、快照复现、证据链和阶段依赖。

它只回答三个问题：

1. 在当前平行校园产品阶段，`docs/Ref` 中的万象 3.0、LivingBrain、因果推理、持续学习和
   涌现认知思想哪些应该被吸收，哪些应该延后，哪些不应该照搬。
2. Roadmap 1 已定义的世界事实层和 Roadmap 2 已定义的观察/编辑层之间，算法和 LLM 应如何
   分工，避免纯规则玩具世界和纯模型幻觉世界。
3. 饥饿、疲劳、压力、预算、地点、时间和制度等约束如何从硬性 if/else 转为软约束多路径
   决策模型。

当前产品路线已经明确：

- 产品 Horizon 1：深化校园物理、空间、经济、信息传播、群体模式和编辑 Agent。
- 产品 Horizon 2：形成可复现、可校准、可导出的社科研究闭环。
- 产品 Horizon 3：再考虑真人数字孪生和更强的长期共生能力。

因此，本文件的核心原则是：

```text
万象 3.0 提供“世界如何按机制运转”的参考；
LivingBrain 提供“系统如何从运行数据中发现规律”的参考；
因果推理和持续学习提供“结果如何校验和回流策略”的参考；
LLM 只承担主观裁决、解释、对话和语义长尾，不创造底层事实。
```

## 4. 当前产品阶段的采用边界

### 4.1 立即采用：机制优先，而不是剧情优先

平行校园不应该预设“第几天发生抗议”“某几个人一定成为朋友”这类剧情结果。当前应继续把精力放在底层机制：

- 空间可达性、容量、开放时间和拥挤；
- 时间预算、身体状态、经济账本和库存；
- 关系、组织、制度程序和权力差异；
- 信息接触、传播路径、失真和信任；
- 事件谱系、快照、分支和可复现审计。

这与万象 3.0 的“世界从机制中自然生长”一致，但在校园产品中要更克制：机制可以产生群体行动候选，不能由系统直接宣布“恐慌”“抗议”“失忆”等社会意义。

### 4.2 立即采用：校园作为第一个世界模板，而不是最终边界

平行校园的长期目标不是只做校园，而是从一个可控小世界扩展到城市、组织、国家乃至全球。
因此，当前实现不能把核心规则写成校园专用 if/else，而应沉淀为可迁移的世界机制原语。

错误方向：

```text
if 地点 == 食堂 and 时间 == 中午:
    去吃饭
if 地点 == 教学楼 and 时间 == 9点:
    上课
```

正确方向：

```text
Need: hunger / rest / income / social / safety / identity
Resource: food / money / time / attention / trust / authority
Place: capacity / access / distance / risk / service
Institution: role / permission / obligation / sanction
Action: preconditions / cost / duration / effect / evidence
```

校园里的“去食堂吃饭”只是这些原语的一种组合：

```text
need = hunger
resource = food
place = canteen
action = consume
cost = money + time + queue
effect = hunger 下降，money 下降，可能产生社交接触
```

同一套原语将来可以表达城市餐馆、公司外卖、医院排队、灾区领物资、国际粮食供给和
全球供应链压力。尺度不同，机制相同。

### 4.3 长期采用：机制内核、场景模板和语义长尾分层

面向全世界扩展，架构必须分三层：

| 层级 | 职责 | 示例 |
| --- | --- | --- |
| 世界机制内核 | 不绑定校园，提供空间、时间、资源、制度、关系、信息、行动、因果、记忆等原语 | `ActionRule`、账本、事件谱系、传播路径、制度案件 |
| 场景/题材模板 | 用配置组合机制原语，形成校园、城市、企业、国家、全球等场景 | 校园课程、城市通勤、公司组织、国家政策、国际贸易 |
| LLM 语义长尾 | 处理命名、解释、候选动作、对话、复杂动机和报告 | 编辑 Agent、异常解释、协商文本、研究报告草稿 |

机制内核回答的是：

```text
谁需要什么？
谁拥有什么？
在哪里？
能不能到达？
有没有权限？
需要多少时间和成本？
会影响谁？
信息如何传播？
制度如何响应？
资源是否守恒？
事件如何追溯？
```

这套问题在校园、城市和全球层面都成立，因此比枚举具体行为更可扩展。

### 4.4 长期避免：把校园名词固化为核心抽象

以下设计会阻碍从校园扩展到全世界：

- 不把底层 action type 固化为大量校园专有动作。`attend_class` 可以是模板标签，
  但核心应抽象为 `participate_in_scheduled_activity`。
- 不把地点字符串作为空间真值。核心应使用空间节点、区域层级、可达性、容量和服务属性。
- 不把制度写成校园专属流程。请假、法院、公司 HR、政府审批都应落到规则、案件、
  证据、授权、决定、申诉和处罚等制度原语。
- 不让 LLM 直接创造事实。世界越大，事实层越必须来自事件、状态、账本、观察和传播。

校园阶段的任务不是完成一个“校园游戏”，而是验证世界机制内核是否可靠：

- 空间是否可靠；
- 资源是否守恒；
- 行动是否可审计；
- 信息是否局部传播；
- 制度是否能响应；
- 群体模式是否能被发现；
- 研究者是否能干预和复现。

### 4.5 立即采用：三级计算触发，控制 LLM 成本

参考万象的 routine / 预测误差思想，平行校园应采用三级触发：

| 层级 | 用途 | 成本策略 |
| --- | --- | --- |
| Level 0 规则惯性 | 上课、移动、排队、消费、休息、开放时间、账本结算、物理状态 EWMA 平滑 | 不调用 LLM，100% 确定性算法 |
| Level 1 结构化策略 | 空间冲突、预算不足、最高支付意愿 WTP 计算、迟到、资源短缺、Intra-tick 备选消费 | 规则、弹性系数、受约束多路径回退 |
| Level 2 深度认知 | 长期计划重构、复杂对话、价值冲突、异常解释、编辑判断 | 受预算、权限和触发条件限制地调用 LLM |

这不是万象原文中的固定分层，而是对平行校园当前成本、安全和稳定性要求的工程化改造。

### 4.6 最新落地核验实例与界面契约 (2026-08-14)

1. **环境物理连续性（EWMA 算法）**：
   环境状态 updates 使用指数加权移动平均算法（Exponentially Weighted Moving Average, $\alpha=0.65$）：
   $$\text{State}_{t} = 0.65 \times \text{Observed}_{t} + 0.35 \times \text{State}_{t-1}$$
   用于消除环境气温与拥挤度数据在跨窗口同步时的骤变，确保物理世界连续稳定。

2. **市场报价与最高支付意愿（WTP）校准**：
   在 `app/market/service.py` 中，最高支付意愿公式引入弹性因子校准 $\text{elasticity\_factor} = \max(1.0, \text{elasticity})$，防止非弹性必需品（如早餐、餐饮）出现人为过度打折。当主报价超限时，自动触发 Level 1 梯度的 Intra-tick 替代消费机制。

3. **前端地图与可视化契约**：
   系统正式确立 **MapLibre 2D Canvas + OSM/WGS84 矢量地理底图** 为全局默认空间入口，承担 Agent 位置、轨迹 lerp 平滑插值、物理状态覆盖层与开放 POI 呈现；原 3D Three.js 场景退居为局部人物档案与特定室内场景的按需加载试图，避免全量 3D 加载引发性能与交互复杂度上升。

### 4.5A 立即采用：软约束多路径决策，而不是固定反应

Roadmap 1 的 `3.6.2A` 已把软约束多路径决策列为内生世界重构的一部分。本文件补充其架构
分工：身体、经济、空间和制度状态不应直接写成“唯一正确动作”，而应转化为候选行动分布。

以饥饿为例，错误实现包括：

```text
hunger > 85 → 必须 consume
hunger > 85 → 不能 reflect，只记录失败
```

更符合真实世界映射的实现是：

```text
hunger=100
→ eat / buy_food / ask_friend / borrow / endure / sleep / violate_rule / collapse
→ 每条路径由资源、地点、时间、人格、关系、记忆和风险共同加权
→ 选择后由统一因果执行器结算身体、账本、库存、关系和记忆后果
```

因此，“真实”不是没有规则，而是规则不直接写死高层行为。规则负责生成机会、成本和后果；
Agent 在这些机会中以异质偏好和有限理性做选择。相同 `hunger=100` 可以在不同 Agent 身上
产生完全不同的行为：有人立刻吃饭，有人忍着，有人借钱，有人睡觉逃避，有人违规，有人崩溃。

### 4.5B 立即采用：算法与模型分工

平行校园的决策栈采用以下边界：

| 层级 | 负责方 | 输入 | 输出 | 禁止事项 |
| --- | --- | --- | --- | --- |
| 世界机制算法 | 确定性/半确定性代码 | 事实状态、资源、空间、账本、时间、规则版本 | 可行机会、成本、风险、成功率、后果模板 | 不直接替 Agent 写主观理由 |
| 结构化策略 | 权重、轻量模型、因果规则 | 身体压力、目标、记忆、关系、资源可达性 | 候选行动分布和 fallback | 不把软约束降级成单一路径 |
| LLM 主观层 | 受预算限制的模型调用 | 候选行动、局部观察、人格、记忆、冲突 | 主观裁决、对话、解释、叙事片段 | 不创造事实，不绕过账本/库存/身体结算 |
| 因果推理 | 干预、反事实、结构学习 | 事件谱系、指标、分支实验 | 因果假设、干预效果、反事实比较 | 不把相关性自动写回世界规则 |
| 持续学习 | 经验回放、策略更新 | 成功、失败、处罚、观察到的他人结果 | 长期偏好、策略权重和适应记录 | 不覆盖历史记忆和证据 |

这意味着：

- 物理可达、库存守恒、账户余额、空间占用和死亡等事实边界必须由算法保证。
- 饥饿、疲劳、压力、预算不足、拥挤和制度阻碍大多数时候是软约束，改变分布而不是固定结果。
- LLM 可以解释“为什么白露这次选择忍着不吃”，但不能凭空让白露吃到不存在的食物。
- 因果推理负责回答“如果开放夜间补给，饥饿失败会不会下降”，不是在 runtime 中擅自改规则。
- 持续学习负责让失败经验影响未来，比如“下次晚上提前买食物”，不是让每次 tick 重新做人。

### 4.6 立即采用：事实层、认知层、传播层分离

参考万象的信息层和当前 Roadmap 2，系统必须严格分离：

- 事实层：事件账本、世界状态、行动日志、账本、库存和空间状态。
- 认知层：Agent 的观察、记忆、信念、假设和误解。
- 传播层：转述、媒体报道、谣言、争议信息和公共声明。

允许 Agent 因信息不对称形成错误信念；不允许 LLM、日报或群体观察器凭空创造底层事实。

### 4.7 近期采用：群体模式观察器和编辑 Agent

这部分已经放入 `ENVIRONMENT_REALISM_ROADMAP2.md`，是当前产品规划中最贴近参考架构的落点：

- Agent 连续性异常：Agent 只能基于自己可接触的证据察觉缺口。
- 群体模式观察器：只输出统计模式候选，不直接生成规范、制度或新闻。
- 校园日报编辑 Agent：可以发布、等待、调查或拒绝，但必须回链事实证据。

这会让产品从“事件流展示”升级为“受证据约束的社会观察系统”，也是产品 Horizon 1 到 Horizon 2 的关键桥。

## 5. LivingBrain 的引入方式

LivingBrain 不应该在当前阶段直接成为 Agent 的行动大脑。原因有三点：

1. 当前产品最紧迫的是生产稳定、世界 tick、空间/经济/传播机制和可观测性。
2. LivingBrain 的强项是从批量观测中发现规律，而不是替每个 Agent 做日常决策。
3. 如果过早让规律发现结果反向改写世界，会混淆“模拟机制”和“研究分析”。

因此建议分三步引入：

| 阶段 | 用法 | 输出边界 |
| --- | --- | --- |
| 产品 Horizon 1 后半 | 离线扫描事件、空间流量、传播路径和账本指标 | 只生成研究候选，不影响运行 |
| 产品 Horizon 2 | 建立 PerceptionBatch 风格的研究输入和指标看板 | 生成假设、报告草稿和实验建议 |
| 产品 Horizon 2 后期 | 接入文献基准、真实统计数据和稳健性检验 | 辅助校准，不自动宣布社会定律 |

可优先尝试的校园观测批次：

- 天气、考试压力、开放时间 → 空间流量；
- 资源短缺、预算压力、价格变化 → 消费与兼职行为；
- 信息来源、关系信任、传播路径 → 信念接受和转述概率；
- 群体模式候选 → 后续规范、制度或关系变化。


## 5A. Research Cortex 工程补充：从观测批次到证据仲裁

外部参考建议中的八个能力适合作为 Roadmap 3 的研究平面补充，而不是运行平面的新主循环。
它们共同服务一个目标：让系统不仅能运行一个世界，还能把运行证据封装为可复现研究对象，
形成可修订假设，并在隔离分支中验证不同选择的后果。

### 5A.1 `WorldObservationBatch`：统一世界观测协议

Roadmap 1 已要求指标具备单位、聚合窗口、来源事件和数据质量说明；本节补充一个工程抽象：
`WorldObservationBatch`，即“一次可复现研究观察的标准封装”。

每个观测批次至少回答：

```text
观察了哪个世界、分支和快照？
观察了哪段 tick / 时间窗口？
观察单位是什么？
变量来自事实、观察、信念还是传播记录？
哪些 Agent 或组织实际暴露于相关条件？
每一行数据能否回链到底层事件、轨迹、账本、观察或外部来源版本？
数据覆盖、重复、延迟和误差如何？
同一快照和批次定义能否重新生成相同结果？
```

第一版只支持有限白名单批次：

- `spatial_flow_batch`：天气、课程、开放时间、容量与空间流量；
- `economic_behavior_batch`：预算、价格、库存、收入与消费/兼职；
- `information_diffusion_batch`：来源、关系、重复暴露与相信/转述/反对；
- `institutional_response_batch`：群体模式、投诉、组织响应与规则变化。

关键边界：没有来源事件不进入正式观测批次；没有实际暴露不计入受干预组；事实、观察和信念
不能混在同一变量中而不标注；不同分支或规则版本不可比时必须返回 `not_comparable`。

### 5A.2 `Hypothesis & Mechanism Registry`：假设与机制注册表

研究层不保存“社会定律”，而保存带适用范围、证据、反证和不确定性的机制候选。至少区分：

- `PatternCandidate`：描述统计模式，不声明因果；
- `MechanismHypothesis`：提出可能机制和中介路径；
- `ValidatedSimulationMechanism`：经过分支实验和机制证据支持的模拟内机制；
- `ExternallyCalibratedFinding`：与真实数据或文献在限定范围内对齐的发现。

每条假设必须绑定至少一个 `WorldObservationBatch`、明确 outcome、scope 和替代解释。支持证据、
反对证据、失败运行和替代解释必须对称保存。`no_reference_found` 不能自动升级为
`novel_discovery`；现实推论与模拟结论必须分开存储。

### 5A.3 `Evidence Arbiter`：证据仲裁器

证据仲裁器负责判断“我们凭什么相信这个结果”，但不能修改运行世界。它不应输出单一置信度，
而应输出证据向量：

```text
data_quality_score
association_score
robustness_score
mechanism_score
causal_score
external_alignment_score
generalization_score
uncertainty
limitations
```

证据阶梯可以从 `E0 insufficient evidence`、`E1 descriptive pattern`、`E2 robust association`、
`E3 mechanism-supported`、`E4 causal-in-simulation` 到 `E5 externally calibrated`。高拟合结果
可能因数据泄露、重复根事件、共同外部冲击、单一随机种子、指标定义错误或 LLM 偏差被拒绝。

第一版仲裁先规则化：来源完整、至少多个观察窗口、无重复根事件、有实际暴露记录、有替代解释
检查，才允许候选从 `candidate` 升级到 `observationally_supported`。

### 5A.4 `World Experiment Planner`：世界实验规划器

实验规划器只读生产事实并提出实验草案，不能自动改 production，不能直接改 Agent 行为，也不能
绕过人工审批。所有实验必须从快照分支启动，干预白名单、开始/结束时间、目标群体、实际暴露、
预算、风险和停止规则都要版本化。

第一版只允许低风险白名单实验，例如开放时间、服务容量、商品价格、补贴比例、信息发布范围、
信息来源可信度、天气冲击、资源供给、课程或活动密度。自由代码干预和高风险心理操纵不进入
默认能力。

### 5A.5 `Knowledge Lifecycle`：知识生命周期

长期运行后，系统会积累模式候选、研究假设、实验结果、编辑线索、Agent 假设和组织经验。
这些知识不能只新增，还必须支持去重、冲突、降权、过期、归档、重激活和版本替代。

通用状态包括：

```text
active / under_review / contested / weakened / superseded / expired / archived / reactivated / rejected
```

任何知识变化不得覆盖历史；旧规则版本产生的结论必须可识别；过期知识不能默认进入新报告；
重激活必须说明新证据。归档不等于删除。

### 5A.6 `Micro–Meso–Macro Bridge`：微观—群体—制度跨尺度桥

Roadmap 1 已要求宏观指标能下钻到底层事实；本节补充“跨尺度桥”的机制表达。宏观现象不能
只是平均值聚合，必须保存微观来源、中间机制、覆盖率、替代解释和规则版本。

第一版优先实现三条桥：

- Agent 移动、时间预算和空间选择 → 空间拥挤、等待、放弃与服务压力；
- 信息接触、关系信任和重复暴露 → 群体传播、信念分布与编辑 Agent 选题；
- 个体交易、库存和预算约束 → 价格压力、资源短缺与组织响应。

跨尺度桥的输出不能反向制造 Agent 事实；中间机制缺失时，只能报告“不完整解释”。

### 5A.7 `Symbolic Candidate Engine`：符号规律候选生成器

符号回归只作为关系候选生成器，不能自动写回世界规则。它只能接收已验证的
`WorldObservationBatch`，并要求训练/验证分离、样本量门槛、变量单位、缺失策略、多重检验控制、
负对照和时间泄露检查。

第一版只处理等待与放弃、信息接受与转述、价格与消费三类问题，每次最多输出少量候选。候选
必须进入 `Hypothesis & Mechanism Registry`，不得直接进入运行规则或 Agent 策略。

### 5A.8 `Real-World Import & Cross-World Meta Analysis`：真实世界导入与跨世界元分析

中期方向不是优先虚构多个校园或城市，而是把真实世界逐步导入系统。系统应能通过类似
Google Earth、Google Maps、开放街图、校园 GIS、楼宇平面图、卫星/街景、公开设施数据或人工校验
等来源，从一个真实学校开始导入：楼、道路、出入口、楼层、自然环境、服务点、开放时间、容量、
通行限制和周边城市连接。

导入流程应分层：

```text
真实地理与建筑数据
→ 空间节点、边、区域、楼层、距离、可达性和容量
→ 服务、资源、制度、开放时间和权限
→ Agent 局部可感知环境
→ 运行事件、轨迹、账本和观察批次
→ 与真实客流、价格、天气、课程或设施数据校准
```

这里的关键判断是：当前 `spatial_nodes` / `spatial_edges` 对真实世界导入有用，应继续作为
runtime graph；但它们不是完整导入架构。真实导入需要新增“翻译层”，把外部世界可靠地转成
当前 runtime 能执行的空间图。

建议采用三层：

| 层级 | 职责 | 示例 |
| --- | --- | --- |
| Raw Import Layer | 保存原始来源、导入批次、坐标系统、置信度和人工校验 | OSM、校园 GIS、楼宇平面图、卫星/街景、手工标注 |
| Canonical Spatial Graph | 统一为可运行空间图、几何、楼层、可达性、服务和准入规则 | `spatial_nodes`、`spatial_edges`、geometry、access rules、services |
| Runtime Spatial State | 只保存运行时状态和事件，不反向修改来源事实 | Agent 位置、路径、占用、队列、资源、观察、空间事件 |

因此，真实世界导入不需要推翻当前拓扑结构，但需要补充以下能力：

- `spatial_import_batches`：记录导入来源、范围、时间、坐标系统、工具版本、校验状态和数据质量。
- `spatial_source_refs`：将内部节点、边、服务和几何对象映射回 OSM/GIS/楼宇图/人工标注等来源。
- `spatial_geometries`：保存 point/line/polygon/floor-plan geometry 或 GeoJSON，不再只依赖 `radius`。
- `spatial_coordinate_transforms`：保存经纬度、投影坐标、本地 Three.js 坐标之间的转换版本。
- `spatial_levels`：表达 campus → zone → building → floor → room/corridor/stair/elevator/entrance 的层级。
- `spatial_access_rules` 与 `spatial_services`：将开放时间、门禁、角色权限、服务窗口、座位、设备和容量从地点标签中拆出。

短期 MVP 不应试图一次导入完整城市。推荐顺序是：

```text
通用 GeoJSON 导入器与 dry run 报告
→ 一个中国校园或真实街区的小范围 bbox 验证
一个真实校园粗粒度导入
→ 主要建筑、道路、入口和服务点
→ 来源追踪、人工校验和坐标转换
→ 一两个关键建筑的楼层/室内结构
→ 用真实客流、开放时间、天气、课程、价格或设施数据校准
```

当前工程采用这一 MVP 路线：先把 OSM/GeoJSON 翻译为现有 `spatial_nodes` / `spatial_edges`，
验证建筑、道路、水体、绿地、铁路、水系、POI 和地形点的导入质量。中国校园数据如果 OSM
覆盖不足，不应立即转向受限商业地图批量抽取，而应使用学校官网地图、政府开放 GIS 或人工校正
补足楼名、入口、容量和开放时间。

`campus_spaces` 长期应降为兼容旧 API 的映射或视图；空间真值应收敛到 canonical spatial graph，
避免出现 legacy 空间状态和 `spatial_nodes` 状态互相矛盾。

因此 Cross-World 的首要含义不是“多宇宙知识锦标赛”，而是比较不同真实世界导入版本、不同数据
精度、不同校准水平、不同时间窗口和不同政策分支下机制是否稳定。可比较对象包括：

- 同一真实学校的不同学期、不同随机种子、不同政策分支；
- 同一学校从粗略地图到精细楼宇导入的不同版本；
- 不同真实学校之间，在指标、观察单位、规则版本和实际暴露兼容时的有限比较；
- 未来真实城市片区、医院、公司园区或灾区供给网络等真实场景。

元分析必须保留每个世界的独立结果，不因汇总隐藏方向相反的结果。不兼容时返回
`not_comparable`。跨世界结论只说明适用范围、稳定条件、失效条件和迁移风险，不自动写回运行规则。

## 5B. 双平面架构边界

上述能力可以概括为双平面：

```text
Runtime Plane：World Reality Core → Agent Experience → Social Meaning
Research Plane：Evidence & Observation → World Research Cortex → Experiment & Governance
```

Runtime Plane 拥有事实写入权。Research Plane 默认只读，只能生成观测批次、假设、仲裁结果、
实验提案和报告；获批实验只能写入隔离分支。任何研究脑、符号候选、编辑 Agent 或 LLM 都不能
绕过 World Reality Core 写入生产事实。

## 6. 不应照搬的部分

以下能力在参考文档中有价值，但不适合当前直接落地：

- 不全量引入每个 Agent 一个 LivingBrain。
- 不把 FEP、量子、梦境、顿悟等概念直接写进当前 Agent 主循环。
- 不让符号回归或幂律拟合结果自动改写规则参数。
- 不引入多宇宙 fork/merge 的知识锦标赛作为近期产品能力。
- 不把模拟内规律包装成现实社会定律或可发表结论。

这些可以作为远期研究方向，但必须等产品 Horizon 2 的数据质量、校准、因果识别和复现实验能力成熟之后再考虑。

## 8. 产品落地优先级

### P0：稳定运行与安全边界

- 修复 world tick、数据库迁移、连接池、锁和恢复问题。
- 补齐 Production / Staging 策略、CI、健康检查、权限和 secret 管理。
- 控制 LLM、数据库、流量和部署成本。

### P1：校园世界机制深化

- 完善空间路径、容量、开放时间、资源和账本结算。
- 将校园行为沉淀为可迁移的世界机制原语，避免把校园名词固化进核心。
- 让 Agent 行动更多由可审计机制决定，LLM 只处理必要的高层认知。
- 加强信息传播、关系、组织、制度和权力反馈。

### P2：Roadmap 2 观察能力

- 主体连续性观察。
- 群体模式候选。
- 校园日报编辑 Agent。
- 观察假设、编辑线索和模式候选的生命周期管理。

### P3：研究闭环

- 建立 `WorldObservationBatch`、指标注册、暴露识别和数据质量评估。
- 引入假设与机制注册表、证据仲裁器和知识生命周期。
- 在人工审批和隔离分支中支持干预实验、A/B 分支、稳健性检验和报告草稿。
- 将符号候选和真实数据校准作为只读研究候选，不自动改写运行规则。

### P4：跨场景扩展

- 将校园模板推广到城市、组织和区域级模板。
- 复用空间、资源、制度、信息、因果和研究观察原语，不重写核心机制。
- 让 LivingBrain 和因果推理服务跨尺度规律发现，而不是服务单一校园场景。

## 9. 证据阶梯

真正的护城河不是机制复杂，而是能证明系统可靠。平行校园应按以下顺序建立可信度：

1. 工程正确性：系统是否稳定运行，tick、迁移、账本和快照是否正确。
2. 内部效度：干预变量是否真的导致观察到的变化。
3. 行为效度：Agent 微观行为是否接近可解释的人类行为分布。
4. 宏观效度：空间流量、网络结构、预算压力、传播速度是否接近真实校园基线。
5. 外部效度：换学校、换时间、换人群后是否仍然成立。
6. 决策效度：是否能帮助研究者提出更好问题、设计实验或辅助真实决策。

LivingBrain 可以帮助攀登第 3-6 级，但前提是第 1-2 级已经扎实。

## 10. 结论

万象 3.0 和 LivingBrain 对平行校园最重要的启发不是“做一个更复杂的大脑”，而是两条产品原则：

1. 世界运行必须来自可审计机制，而不是剧本和幻觉。
2. 系统学习必须来自可追溯数据，而不是把拟合结果直接当真理。

当前最适合的路线是：先稳住生产运行和机制事实层，再完成 Roadmap 2 的观察/编辑能力，最后把 LivingBrain 式规律发现接入产品 Horizon 2 的研究闭环。

校园是最小可控世界，不是最终边界。今天的食堂排队、图书馆拥挤和校园谣言，应被设计成
未来城市交通、医院拥堵、供应链危机和全球信息传播的最小模型。
