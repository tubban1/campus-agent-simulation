# 校园 Agent 平行世界：空间社会智能升级路线

## 1. 文档目的

本文定义校园 Agent 平行世界从“语言驱动的多 Agent 展示系统”升级为“可观察、可干预、可复现、可解释的空间社会智能实验平台”的产品方向与工程路线。

本文是后续空间智能相关需求、架构设计、实验设计和阶段验收的共同依据。具体实现仍应拆分为独立功能分支和 PR，不在本路线文档 PR 中直接修改运行代码。

阶段编号以 `ENVIRONMENT_REALISM_ROADMAP.md` 为准。本文是空间子路线，不再维护独立的“空间阶段 0-5”主线。

当前状态：

- 环境与因果底座阶段 0 已完成。
- 统一主路线阶段 1A-1F 已完成，下一项是阶段 2 的空间社会行为与统一经济社会机制。
- `spatial-foundation-design.md` 是阶段 1A 的详细技术设计。
- 路径、容量、感知和空间社会行为必须建立在同一空间真值与轨迹证据上。

## 2. 项目定位

### 2.1 当前基础

当前系统已经具备：

- 校园 Agent 的角色、目标、记忆、关系、位置和日程。
- 教学楼、图书馆、食堂、宿舍区、商业街、操场、校务处等校园空间。
- 天气、时间、拥挤度、空间开放状态和校园事件。
- Agent 感知、记忆检索、决策、规则执行、反馈和沉淀闭环。
- Three.js 校园展示、人物详情、关系网络、行动时间线和校园日报。
- SQLite/PostgreSQL 持久化与 Render 部署基础。

当前的空间仍主要表现为地点标签和空间状态。Agent 可以决定“前往图书馆”，但尚未完整理解道路、入口、距离、视线、遮挡、局部人流和沿途接触。

### 2.2 目标定位

项目的下一阶段目标是：

> 构建一个具有有限感知、空间记忆、路径约束和社会关系的校园实验世界，研究空间条件如何影响个体行动、群体形成、信息传播和政策干预结果。

空间智能不是单纯增加更精细的 3D 画面，而是让空间成为能够约束感知、决策、行动和社会关系的计算系统。

## 3. 核心原则

### 3.1 世界真实状态与 Agent 主观认知分离

系统必须区分：

- 世界中真实存在的对象、人物、事件和空间状态。
- Agent 当前能够看见、听见或接触到的信息。
- Agent 从他人、公告或外部资讯获得的信息。
- Agent 根据记忆和经验形成的推测。
- Agent 尚不知道或判断错误的内容。

Agent 不应直接读取完整世界数据库作为决策上下文。

### 3.2 LLM 与确定性空间引擎分层

LLM 负责：

- 社会意图。
- 目标权衡。
- 对话与协商。
- 高层行动选择。
- 对经历的解释和反思。

空间与规则引擎负责：

- 距离和路径计算。
- 开放状态与容量检查。
- 移动时间和能量成本。
- 视线、邻近和遮挡判断。
- 碰撞、排队和空间占用。
- 真实世界状态写入。

LLM 不直接修改坐标，也不能绕过空间规则。

### 3.3 研究证据优先于叙事效果

每次空间行动都应形成可追踪证据链：

```text
世界状态
→ Agent 可感知范围
→ Agent 主观空间模型
→ 检索到的空间记忆
→ 社会目标与空间计划
→ 规则执行结果
→ 世界、关系与记忆变化
```

个人日记和校园日报是运行结果的叙事摘要，不能代替底层实验数据。

### 3.4 可复现优先于规模

在扩大 Agent 数量或接入高精度物理引擎之前，优先完成：

- 实验批次编号。
- 随机种子。
- 配置快照。
- 世界状态快照。
- 暂停、恢复和回放。
- 统一时间字段。
- 研究数据导出。

### 3.5 连续开放空间优先于地点标签

空间不能只是“图书馆、食堂、操场”这样的地点标签，也不能只在 Agent 访问时临时生成。
真实空间应持续存在、持续变化，并在 Agent 离开后保留痕迹：

- 人、对象、噪声、光照、拥挤、道路状态和服务能力随时间连续变化。
- Agent 对空间的理解来自局部观察、他人转述、公告和记忆，而不是完整数据库。
- 空间中的门、座位、设备、商品、垃圾、公告和遗留物可以被操作、占用、损坏、修复或移动。
- 多人活动从共处、接近、共同路线、共享对象、会话轮次和结果中被后验识别。
- 空间状态必须能解释“为什么发生”和“为什么没发生”，例如未遇见、没看到、太远、
  太累、太挤、设备被占用、路线绕行或服务已经停止。

## 4. 目标能力模型

### 4.1 校园空间图

每个空间至少包含：

- 唯一标识和名称。
- 空间类型与功能标签。
- 二维或三维坐标。
- 空间边界。
- 容量和当前占用。
- 开放时间和运行状态。
- 入口、出口和相邻空间。
- 噪声、照明、安全和资源状态。

道路或连接边至少包含：

- 起点和终点。
- 距离和基础耗时。
- 通行状态。
- 拥堵系数。
- 天气影响系数。
- 无障碍属性。
- 风险等级。

### 4.2 连续移动

移动不再是地点字段的瞬时切换，而是一个可中断的连续过程：

```text
选择目的地
→ 规划路径
→ 进入路径节点
→ 消耗时间与能量
→ 产生沿途感知和接触
→ 到达或重新规划
```

空间关闭、道路拥堵、天气变化和突发事件可以触发重新规划。

### 4.3 局部感知

Agent 的感知由以下因素决定：

- 当前位置与朝向。
- 感知半径。
- 空间边界和遮挡。
- 光照与噪声。
- 目标对象的距离。
- 注意力和当前任务。
- 信息渠道。

感知结果必须记录来源、时间和置信度。

### 4.4 空间记忆

空间记忆至少记录：

- 发生时间。
- 具体位置。
- 观察位置和信息来源。
- 附近人物与对象。
- 事件内容。
- Agent 的行动与结果。
- 重要性和可信度。

空间记忆应参与后续目的地选择、路径规划、风险回避和社交决策。

### 4.5 空间社会行为

后续逐步支持：

- 人际距离和个人空间。
- 身体朝向和共同关注目标。
- 排队与插队。
- 偶遇、同行和回避。
- 小群体站位与 F-formation。
- 拥挤导致的移动成本、压力和冲突。
- 长时间共处对熟悉度和关系的影响。

### 4.6 空间实体与共享环境

空间不能只提供坐标、容量和开放状态，还必须承载可被 Agent 操作并持续变化的具体对象：

- 门、围栏、座位、储物柜、教学设备、运动设施、商品、垃圾和维修对象。
- 对象支持的可用能力，例如打开、关闭、占用、使用、移动、拾取、放下、损坏和维修。
- 独占、共享、预约、排队、所有权、权限、耐久度、故障和恢复。
- Agent 行动造成的对象状态变化，以及其他 Agent 对变化的局部感知。
- 经共享对象产生的间接交互，例如抢占座位、设备排队、遗留物、噪音和设施损坏。
- 对象自然过程，例如磨损、污染、老化、天气暴露、补货、清洁、维修和服务恢复。
- 对象和空间过程可以触发新的 affordance，例如积水后绕路、球场有空位后发起运动、
  公告张贴后传播消息、设备故障后出现求助或维修活动。

对象状态必须属于世界真值，并通过事件保存变化前后值、操作者、位置、持续时间和来源行动。
对象不能因为离开前端视野或进入下一 tick 而自动恢复。

### 4.7 后验空间活动识别

空间社会行为不应主要靠预置活动标签生成。系统应先记录原子事实，再用识别器将事实聚合
为可读活动：

```text
轨迹 + 共处 + 距离 + 会话 + 对象占用 + 资源消耗 + 关系/身体/记忆结果
→ 候选活动
→ 置信度、参与者角色、开始结束时间、地点和证据链
```

例如“一起吃饭”需要实际到达食堂或其他进食地点、存在食品或服务、出现购买/领取/分享、
共同停留和交流证据；“一起打球”需要运动空间、器材或场地占用、多人轮换或协作/竞争、
身体消耗和活动结束；“一起旅行”需要共同路线、跨空间或外部空间移动、交通或时间成本、
共同目标和多 tick 持续证据。

识别器可以给活动命名，但不能反向制造行动、坐标、账本、对象状态或记忆。

## 5. 统一主路线中的空间实施计划

### 阶段 1A：空间真值层

目标：先让空间成为稳定、可查询、可快照恢复的世界事实。

主要任务：

- 建立 `spatial_nodes` 与 `spatial_edges`，统一节点代码、坐标、边界、容量和环境属性。
- 建立 `agent_spatial_states`，保证每位 Agent 只有一个当前空间真值。
- 定义移动速度、无障碍需求、基础感知半径等空间能力字段，后续阶段分段启用。
- 建立按实验运行、世界分支和 tick 定位的不可变轨迹。
- 将 `residents.location` 保留为过渡期兼容字段，新空间逻辑只读空间服务。
- 提供场景图、占用、Agent 空间状态和轨迹 API。
- 将空间真值纳入世界快照、恢复校验和研究导出。

验收标准：

- 七个主空间拥有稳定节点代码、坐标和连接拓扑。
- 每位 Agent 拥有唯一空间状态，旧地点字段与其保持一致。
- 空间路由不直接执行 SQL，`app/main.py` 只保留编排和 router 注册。
- 初始化、回填和快照恢复在 SQLite/PostgreSQL 上行为一致。
- 原有页面和 Agent 生命周期没有行为回归。

### 阶段 1B：路径规划与连续移动

目标：让 Agent 在有距离和通行约束的校园中移动。

实施状态：已完成。当前移动按真实经过时间和个体速度推进，路径成本包含道路状态、天气、拥堵、风险与基础无障碍约束；在途坐标、路线和轨迹由后端提供给 Three.js。

主要任务：

- 使用 A* 或 Dijkstra 规划路径。
- 为 Agent 记录目标节点、路径、移动进度和预计到达时间。
- 将天气、拥堵、开放状态、风险、移动能力和基础无障碍约束纳入路径成本。
- 移动按 tick 推进，并支持暂停、中断和重新规划。
- Three.js 读取后端坐标和路径，展示当前移动而非前端猜测位置。

验收标准：

- Agent 不能穿越未连接空间或关闭入口。
- 同一目的地可以根据环境产生不同路线。
- 移动成本、沿途节点和重规划原因可以从轨迹重建。

### 阶段 1C：空间准入与时间制度

目标：让空间和制度能够拒绝、延迟或改变行动。

实施状态：已完成。开放时间、维护状态、容量和具体服务资源已经成为出发、到达与目的地行动约束；FIFO 等待、服务速率、放弃和替代地点均形成事件与轨迹证据。

主要任务：

- 执行开放时间、门禁、入口、维护、容量和具体资源规则。
- 将座位、设备、窗口和服务速率纳入可用性。
- 实现由资源不足产生的等待、拒绝、放弃、错峰和替代地点。
- 将课表、饭点、截止日期、闭馆和活动窗口连接到空间行动。

验收标准：

- 空间行动失败或延迟具有结构化环境原因。
- 等待、迟到、改道和替代选择能进入事件流与后续决策。
- 图书馆关闭和食堂拥挤可以成为可重复的机制实验。

### 阶段 1D：身体状态对空间行动的约束

目标：让移动和等待产生真实成本，并让恢复占用时间。

实施状态：已完成。身体存量随 world tick 和行动确定性变化；行动前置条件会因疲劳、饥饿、健康或注意力不足而失败，实际移动速度会根据疲劳、饥饿和健康从基础步速下调。身体状态已进入快照、API、轨迹速度证据和前端异常提示。

主要任务：

- 将体力、疲劳、饥饿、压力和天气暴露连接到移动成本。
- 将身体能力与无障碍需求连接到路径可达性。
- 让休息、吃饭和恢复改变后续路径与行动可用性。

验收标准：

- 相同路线对不同 Agent 具有可解释的成本差异。
- 身体状态能够触发停留、改道、放弃或求助。
- 状态变化来自轨迹和行动，不由叙事文本直接生成。

### 阶段 1E：局部感知与空间记忆

目标：限制 Agent 的知识范围，并让空间经历影响未来决策。

实施状态：已完成。局部视觉、听觉和亲历证据按 Agent 坐标与感知半径生成，远处事件不会进入决策上下文；定向资讯只对实际接收者可见。观察形成可更新信念和带地点、置信度、显著性、效价的空间记忆，后者参与地点权重。观察者关注仅改变观察界面，不改变 Agent 行动、提示或记忆。

主要任务：

- 实现邻近、视野、遮挡、噪声和照明对感知的影响。
- 区分亲眼观察、听闻、公告、记忆和推断。
- 建立带观察位置、来源、距离、时间和置信度的空间记忆。
- 在决策日志中保存 Agent 当时实际可用的信息。

验收标准：

- 不同位置的 Agent 对同一事件拥有不同认知。
- Agent 不能使用未感知或未接收的信息进行决策。
- 历史空间经历能够改变路线、目的地或风险判断。

### 阶段 2：空间社会行为

目标：在有限感知、真实接触和共享环境的基础上，让群体结构与间接影响从空间共处中产生。

实施审计（2026-07-30）：部分完成。runtime 已能生成闲聊、社团活动、协作和冲突等
社会行动，并保存部分关系与互动记录；但自主互动仍主要由发起者单步结算，接收者缺少独立
响应，且互动对象存在脱离局部接触范围的退化选择。移动、容量和资源约束已经存在，但具体
环境对象的操作、持续状态和经环境介导的 Agent 间接互动尚未完整实现。完整实施顺序和
跨领域验收以 `ENVIRONMENT_REALISM_ROADMAP.md` 的 `2.11` 为准。

主要任务：

- 记录位置、接触距离、可见性、共同停留时长、同行和共同关注。
- 面对面互动只从满足局部接触资格的 Agent 中选择，删除全局居民候选退化路径。
- 让接收者基于局部感知、注意力、身体状态、关系和风险独立接受、拒绝、忽略、反提议
  或离开。
- 保存有界多轮互动及每名参与者不对称的判断、记忆与关系后果。
- 实现社会性排队、插队、个人空间、回避和小群体站位。
- 将实际空间接触纳入关系变化与信息传播。
- 为具体空间对象定义可用能力、独占/共享方式、耐久度、故障、维修和状态转换。
- 让对象占用、短缺、损坏、遗留、噪音和拥挤形成可持续、可感知的间接影响。
- 建立空间活动识别器，从底层轨迹、接触、对象和会话证据中识别吃饭、打球、旅行、
  会议、围观、冲突、协作和回避等活动。
- 增加人流热力图、接触网络和轨迹回放。

验收标准：

- Agent 的交流对象受到实际空间接触约束。
- 每次面对面互动都能追溯到位置、距离、持续时间和感知证据。
- 接收者能够改变、拒绝或中断互动，关系结果不由发起者单方面决定。
- 拥挤能够影响等待、情绪、冲突和关系。
- 支持三人以上互动，并能从轨迹、接触、会话轮次和结果数据重建关键群体事件。
- 共享对象不存在重复独占，状态变化在操作者离开后仍然保留并可被他人感知。
- 可以从轨迹、对象状态和事件重建一个 Agent 如何通过环境间接影响另一个 Agent。
- 高层活动必须可以下钻到原子空间事实；没有证据时不能只凭叙事生成活动。
- 相同初始状态与随机种子能够复现接触选择和互动结果。

### 阶段 4：空间研究实验与分析

阶段 3 的开放世界、人口流动和长期适应由环境主路线统一推进；空间子路线在阶段 4 提供研究分析能力。

轨迹授权、位置隐私、导出范围、失败运行保留和实验审计从阶段 1A 开始执行，不等待阶段 4。

主要任务：

- 支持基线、干预、恢复和批次对照。
- 固化三个空间智能基准实验。
- 导出 Agent-Action、Space-Time、Trajectory、Contact Edge、Relationship Edge 和 Event Stream。
- 建立描述统计、时间序列、网络分析和空间热力图。

验收标准：

- 每个实验有明确的自变量、因变量和对照条件。
- 实验结果可以从底层数据而非日记文本中验证。
- 研究报告能够明确区分模拟结果与现实结论。

### 阶段 4 后：高精度物理能力评估

仅在以下研究需求成立时评估 Unity、Unreal Engine、Omniverse 或 Isaac Sim：

- 高密度人群碰撞与疏散。
- 机器人或 Agent 对物体的抓取和协作操作。
- 复杂建筑内部导航与精确遮挡。
- 力矩、重心和刚体动力学。

在此之前，优先使用 Three.js、空间图和确定性规则引擎完成社会研究所需能力。

## 6. 三个基准实验

### 6.1 图书馆关闭实验

研究问题：关键学习空间关闭后，Agent 如何重新规划路径，替代空间是否产生拥挤，接触网络是否发生变化？

主要指标：

- 路径变化和额外移动成本。
- 各空间人流变化。
- 到达失败和重新规划次数。
- 偶遇、聊天、合作和冲突变化。
- 关系网络变化。

### 6.2 食堂拥挤实验

研究问题：排队、容量和个人空间如何影响等待、回避、情绪及冲突？

主要指标：

- 排队长度和等待时间。
- 放弃、换队和错峰行为。
- 人际距离与冲突事件。
- 服务效率和满意度。

### 6.3 局部资讯传播实验

研究问题：当资讯只有部分 Agent 可见时，空间接触和信任关系如何共同影响传播？

主要指标：

- 首次感知位置和时间。
- 传播路径与传播层级。
- 空间接触边与信任边的贡献。
- 未接收、误传和延迟接收情况。

## 7. 建议的数据层

- `Experiment Run`：实验批次、配置、随机种子、代码版本和模型版本。
- `World Snapshot`：指定 tick 的环境、空间、Agent 和事件状态。
- `Spatial Capability`：Agent 移动、无障碍和基础感知能力及其来源版本。
- `Agent Trajectory`：Agent、时间、坐标、路径节点和移动状态。
- `Perception Record`：观察者、目标、来源、距离、置信度和时间。
- `Contact Event`：相关 Agent、位置、距离、持续时间和互动结果。
- `Space-Time`：空间状态、容量、占用、拥挤度和开放状态。
- `Action Evidence`：感知、记忆、计划、执行、反馈和成本。
- `Relationship Edge`：关系方向、信任、合作、竞争、冲突和更新时间。

具体表结构和 API 契约应在对应实现阶段单独设计和评审。

## 8. 非目标

本路线当前不以以下内容为目标：

- 通过增加 Agent 数量制造表面复杂度。
- 将更精细的 3D 美术等同于空间智能。
- 让 LLM 直接控制坐标、碰撞或数据库写入。
- 在没有随机种子和对照实验时宣称因果结论。
- 使用模拟结果评价具体真实学生或群体。
- 在社会研究需求尚未明确时引入高成本物理引擎。

## 9. 项目级成功标准

当以下条件同时满足时，可以认为项目完成了从校园 Agent 展示系统到空间社会智能实验平台的关键升级：

- Agent 的知识受到位置、视野、经历和信息渠道限制。
- 空间能够拒绝、延迟或改变 Agent 的行动。
- 移动、接触、拥挤和关系变化形成完整数据链。
- 空间干预能够产生可追踪的直接与间接影响。
- 同一实验可以通过批次、配置和随机种子复现。
- 研究者可以导出数据并解释每个关键行为的证据来源。
- 产品界面能够回放轨迹、感知、决策和世界变化。

## 10. Git 与交付约定

- 不直接在 `main` 上开发。
- 每个阶段从最新 `main` 创建 `feat/...`、`fix/...` 或 `docs/...` 分支。
- 单个 PR 只承担一个清晰目标。
- PR 必须说明变更内容、验证方式、数据库影响、环境变量影响和部署配置影响。
- 数据结构变更必须附带迁移和回滚说明。
- 合并后由部署平台从 `main` 发布，功能分支不直接作为正式线上版本。
