# 校园 Agent 平行世界社会科学研究使用说明

本文档面向高校、研究机构、实验室和社会科学研究团队，说明如何把校园 Agent 平行世界用于社会仿真研究、教学演示和政策沙盘推演。

本系统不是对真实学生群体的直接测量，而是一个可观察、可干预、可记录的虚拟校园社会。它适合用于机制探索、假设生成、实验设计预演和复杂社会过程可视化。

## 系统能模拟什么

系统中的每个 Agent 都有角色、目标、记忆、关系和当前位置。世界会持续推进，Agent 会在校园空间中观察、移动、交流、形成关系、响应事件，并把经历写入记忆和事件流。

校园世界包含：

- Agent 个体：学生、教师、商户、管理者等角色。
- 校园空间：教学楼、图书馆、食堂、宿舍区、商业街、操场、校务处。
- 社会关系：好感、信任、合作、竞争、冲突。
- 事件流：行动、观察、外部资讯、天气、admin 干预、观察者进入。
- 世界运行时：真实时间同步、tick 推进、模型预算。
- 观察者视角：用户可以观察某个 Agent 或地点。
- 管理员干预：admin 可以启动/暂停世界、推进 tick、注入事件。

## 适合研究的问题

### 1. 空间如何影响互动

可以研究：

- 哪些地点更容易产生互动。
- 拥挤度是否影响冲突、移动或回避行为。
- 图书馆、食堂、宿舍区等空间是否形成不同的社会功能。
- 空间关闭或维修是否改变 Agent 的关系和行为路径。

可用数据：

- Agent 位置
- 空间拥挤度
- 空间事件
- Agent 行动日志
- 世界事件流

### 2. 信任网络如何影响信息传播

可以研究：

- 外部资讯如何沿关系网络扩散。
- 高信任关系是否更容易传播信息。
- 中心人物是否加速信息扩散。
- 孤立 Agent 是否更晚接收信息。

可用数据：

- `relationships`
- `relationship_dynamics`
- `external_information`
- `agent_information`
- `world_event_stream`

### 3. 小群体如何形成

可以研究：

- Agent 是否形成稳定小团体。
- 合作和竞争如何改变群体边界。
- 群体目标是否提升内部信任。
- 冲突是否导致分裂或边缘化。

可用数据：

- 关系网络
- 协作记录
- 竞争记录
- 群体目标
- Agent 行动日志

### 4. 观察者如何影响仿真世界

本系统特别适合研究“被观察性”。用户进入页面后，可以关注某个 Agent 或地点。系统会记录观察者 session，并可能让被关注 Agent 更容易在后续 tick 中被处理。

可以研究：

- 被观察 Agent 是否产生更多事件。
- 观察焦点是否造成记录偏差。
- 观察者关注是否改变世界叙事。
- 观察者偏好是否让某些空间或角色更突出。

可用数据：

- `observer_sessions`
- `world_event_stream`
- 被观察 Agent 的行动日志
- 被观察前后的记忆和事件变化

### 5. 干预政策如何影响校园运行

admin 可以注入事件，例如：

- 图书馆临时关闭。
- 食堂价格调整。
- 组织校园活动。
- 发布外部新闻。
- 提升某类空间拥挤度。

可以研究：

- 干预前后 Agent 行为是否变化。
- 哪些角色受影响最大。
- 干预是否通过关系网络扩散。
- 干预是否增加合作或冲突。

可用数据：

- admin 事件
- 空间状态
- Agent 行动日志
- 关系网络
- 事件流

## 推荐研究设计

### 观察性研究

目标：不主动干预，让世界自然运行。

流程：

1. 启动世界运行时。
2. 固定观察窗口，例如 7 天或 30 天。
3. 不注入 admin 事件。
4. 记录所有事件、关系变化、空间状态和 Agent 行动。
5. 导出数据后分析行为模式和关系结构。

适合问题：

- 虚拟校园是否自然形成稳定社交结构。
- 不同角色是否有不同空间使用偏好。
- 信息是否自然集中到少数中心 Agent。

### 干预性研究

目标：比较干预前后变化。

流程：

1. 运行一段基线期。
2. 注入明确干预，例如“图书馆维修关闭 1 天”。
3. 继续运行观察期。
4. 比较干预前后 Agent 行为、空间使用、关系网络。

建议至少导出：

- 干预事件时间点
- Agent-Tick 数据
- Space-Time 数据
- Relationship Edge 数据
- Event Stream 数据

适合问题：

- 空间限制如何改变群体互动。
- 管理政策是否造成新的拥挤或冲突。
- 某些 Agent 是否成为协调者。

### 对照实验

目标：比较不同设定下的结果。

当前系统还没有完整多世界并行能力，但可以用不同运行批次做近似对照。

建议：

- 保留每次运行的导出数据。
- 记录 git commit、配置、模型预算、运行时间。
- 不要混合不同批次的数据。
- 如果后续支持随机种子，应固定随机种子。

适合问题：

- 高模型预算和低模型预算是否产生不同复杂度。
- 有观察者和无观察者是否产生不同事件分布。
- 不同 admin 干预是否有不同效果。

## 可以产出的分析

### 描述统计

- 每天事件数。
- 每个 Agent 行动数。
- 每个空间访问量。
- 每类行为比例。
- 模型调用次数和成本。

### 时间序列

- 事件随时间变化。
- 空间拥挤度变化。
- 某个 Agent 行为轨迹。
- 干预前后变化。

### 社会网络分析

- 中心性。
- 小团体。
- 关系强弱分布。
- 信任网络和冲突网络对比。
- 信息传播路径。

### 行为序列分析

- 常见行动序列。
- 从观察到移动、从移动到聊天的转移概率。
- 计划行动和实际行动的偏离。

### 叙事分析

- Agent 日记和记忆中的主题。
- 新闻和事件流中的高频议题。
- 冲突或合作事件的叙事链。

## 研究数据的解释边界

使用本系统时需要明确：

- Agent 是模拟角色，不是真实人类受试者。
- 结果不能直接推广到真实校园。
- LLM 输出带有模型偏差。
- 观察者行为会改变数据记录密度。
- admin 干预会改变自然运行过程。
- 模型预算会影响行为复杂度和细节程度。

因此，本系统更适合回答：

- “如果采用某种机制，可能出现什么社会过程？”
- “某个理论假设在沙盘里是否能形成可观察模式？”
- “某类干预可能产生哪些连锁反应？”

不适合直接回答：

- “真实学生一定会如何行动？”
- “某政策在真实校园必然有效吗？”
- “某个群体的真实心理状态是什么？”

## 伦理建议

如果只使用虚拟 Agent，不涉及真人数据，伦理风险较低。但如果研究中加入真实用户输入、真实校园数据或学生行为记录，需要：

- 告知参与者数据用途。
- 获得同意。
- 脱敏个人信息。
- 限制导出权限。
- 保留 admin 操作审计。
- 避免把模拟结论当作真实个体判断。

不要把真实学生姓名、学号、联系方式或敏感经历写入 Agent 记忆。

## 面向机构的使用流程

1. 明确研究问题。
2. 确定观察窗口和干预方案。
3. 配置世界运行状态和模型预算。
4. 运行基线期。
5. 如需要，执行 admin 干预。
6. 导出研究数据。
7. 进行统计、网络、行为序列或叙事分析。
8. 在报告中明确仿真边界和不能推广的部分。

## 示例研究方案

### 方案 A：图书馆拥挤度对社交行为的影响

研究问题：

图书馆拥挤是否会让 Agent 转移到其他空间，并增加或减少社交互动？

设计：

- 基线运行 3 天。
- admin 注入“图书馆座位紧张”事件。
- 继续运行 3 天。
- 比较图书馆、教学楼、食堂的人流变化和聊天事件数量。

主要指标：

- 图书馆访问量。
- 移动次数。
- 聊天次数。
- 冲突指标变化。
- 事件流中的空间相关事件。

### 方案 B：信任网络对外部资讯扩散的影响

研究问题：

高信任关系是否让外部资讯更快传播？

设计：

- 同步一条外部资讯。
- 记录最初接收 Agent。
- 观察后续传播路径。
- 对照关系网络中的信任值。

主要指标：

- 接收资讯的 Agent 数。
- 传播层级。
- 平均传播时间。
- 高信任边和低信任边的传播差异。

### 方案 C：观察者关注是否造成记录偏差

研究问题：

被观察 Agent 是否更频繁出现在事件流中？

设计：

- 运行无观察者基线。
- 让观察者持续关注某个 Agent。
- 比较被关注 Agent 与未关注 Agent 的事件数、记忆数、tick 处理次数。

主要指标：

- `observer_sessions`
- Agent 事件数。
- 记忆数量和重要性。
- tick 中被处理次数。

## 对外介绍摘要

校园 Agent 平行世界是一个可观察、可干预、可导出的社会仿真环境。它把校园空间、虚拟角色、关系网络、事件流和真实时间运行机制结合起来，使研究者可以探索社会互动、信息传播、空间行为、观察者效应和政策干预的动态过程。它不是替代真实调查，而是用于理论探索、假设生成、教学演示和干预预演的研究沙盘。
